# v0.17.2 — High priority fixes

Addresses all 8 HIGH priority issues from the codebase audit (`.claude/notes/2026-03-20-6.md`).
Issue #10 (web device key in localStorage) was intentionally skipped — the risk/complexity of Web Crypto wrapping outweighs the incremental security gain; documented limitation with existing console.warn is sufficient.

## Changes

### Phase 1: Simple Bug Fixes

- **Issue #9** (`app/index.tsx`): Wired `existingIds={journals.map((j) => j.id)}` prop to `NewJournalModal` — cloud import "already local" detection was broken because the prop was never passed from the parent.

- **Issue #11** (`src/contexts/JournalKeyContext.tsx`): Fixed auto-lock interval accumulation by using a `clearAllRef` pattern. Both the AppState listener and the periodic interval effect now have empty dependency arrays and access `clearAll` through a ref, preventing effect re-registration on every `clearAll` identity change.

- **Issue #14** (`src/contexts/SyncManagerContext.tsx`): Fixed untracked promise in `scheduleSyncDebounced` by capturing `managerRef.current` at call time and checking it hasn't changed by resolution time. Added `.catch()` for OAuth token failures.

### Phase 2: Data Integrity Fixes

- **Issue #13** (`packages/canto-data/src/format.ts`): `deserializePages()` now calls `validatePage()` on each parsed page instead of blind `as Page` cast. Callers with existing try-catch will surface validation errors naturally.

- **Issue #8** (`src/lib/backup/import.ts`, `import.web.ts`): Malformed ZIP attachment filenames are now collected in a `skippedAttachments` array and returned in `ImportResult`. Both native and web versions updated identically. `ImportResult` extended with optional `skippedAttachments?: string[]`.

- **Issue #12** (`src/lib/sync/engine.ts`): `downloadPageAttachments` now throws on null download instead of silently skipping, preventing pages from being saved with stale remote paths. The sync engine's existing per-page error handling catches and reports the failure.

### Phase 3: Re-encryption Safety

- **Issue #7** (`src/components/journal/JournalSettings.tsx`): Wrapped `reencryptJournal` call in try-catch. On failure, the original derived key is restored to the cache so the user can still access their data, and the error message confirms the original password still works.

- **Issue #6** (`src/lib/encryption/device.ts`, `device.web.ts`, `SecuritySettingsModal.tsx`): Replaced one-shot `rotateKey()` with two-phase `prepareKeyRotation()` + `commitKeyRotation()`. The new key is only persisted to SecureStore/localStorage after re-encryption succeeds, preventing the catastrophic scenario where the new key is active but data is still encrypted with the old key. Both native and web implementations updated.

## Tests
