## Encryption key caching design

PBKDF2 with 600k iterations is intentionally slow (~200-500ms). Rather than running it on every read/write, the derived key is computed once when the user unlocks a journal and cached in `JournalKeyProvider` (a `Map<journalId, Uint8Array>` stored in a ref). The cached key is used directly with AES-GCM for all subsequent operations. Keys are zeroed on clear.
