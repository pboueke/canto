# Backup & Import — Requirement 9

Implementation of journal export/import via `.canto.zip` files.

---

## Architecture

- **Export** (`src/lib/backup/export.ts`): Serializes journal metadata, settings, pages, and attachments into a ZIP file using `jszip`. Optionally encrypts all content with the journal's password-derived key (AES-256-GCM). Attachments are stored as raw base64 (unencrypted export) or as ciphertext strings (encrypted export). Uses `expo-sharing` to open the system share sheet.
- **Import** (`src/lib/backup/import.ts`): Reads a `.canto.zip`, extracts manifest, optionally decrypts, generates new UUIDs for all entities, saves through `LocalStore` (which applies device encryption). Supports password re-encryption of attachments that were originally encrypted.
- **Conflict resolution** (`src/lib/backup/conflicts.ts`): Case-insensitive name conflict detection with `(copy)`, `(copy 2)`, etc. suffix generation.
- **UI** (`src/components/home/NewJournalModal.tsx`): Import flow integrated into the "new journal" modal — file picker → manifest inspection → optional password prompt → optional rename → import with progress.
- **Export UI** (`src/components/journal/ExportJournalModal.tsx`, `ExportMenu.tsx`): Export menu in journal header with encryption toggle, progress indicator.

## ZIP Structure

```
manifest.json          — always plaintext, contains version, encrypted flag, salt, kdfIterations
journal.json           — journal metadata (encrypted if encrypted export)
settings.json          — journal settings (encrypted if encrypted export)
pages/{id}.json        — one file per page (encrypted if encrypted export)
attachments/{type}-{id}.{ext} — attachment binary data
```

## Key Design Decisions

1. **Two-phase password handling on import**: `needsPassword` (required — encrypted ZIP) vs `canProvidePassword` (optional — unencrypted ZIP of a secure journal, shows Skip button).
2. **Auto-derive for non-secure journals with salt**: When importing an unencrypted backup that has a salt (journal had password removed), the import auto-derives a key with empty password to re-encrypt attachments. This matches the original journal's behavior where the journal screen's auto-derive effect transparently handles these journals.
3. **readEncrypted fallback**: `readEncrypted` in `local.ts` now gracefully falls back to device-decrypted content when password decryption fails. This prevents a chicken-and-egg problem: auto-derive needs the journal loaded, but if metadata were password-encrypted, it couldn't load without the key.
4. **Metadata saved without password key for non-secure imports**: Only `secure: true` journals get password-encrypted metadata/pages. Non-secure journals with encrypted attachments save metadata device-only, but preserve `salt`/`kdfIterations` so auto-derive works after import.
5. **Attachment encryption flags are source of truth**: Export preserves `encrypted` flags from page data as-is, regardless of `journal.secure`. The `secure` flag controls the password prompt; individual attachment `encrypted` flags control which carousel they appear in.

## Bug Fixes Applied During Development

1. **Invalid base64 on device import**: `File.text()` corrupts binary ZIP data as UTF-8 → switched to `File.bytes()` returning `Uint8Array`
2. **Duplicated/missing attachments**: All imported attachments named `imported.{ext}` → same disk path hash collision. Fixed by preserving original attachment name from page data.
3. **Encrypted attachments lose encryption**: Import forced `encrypted: false`. Fixed by tracking `wasEncrypted` and re-encrypting with `saveAttachment(..., derivedKey)`.
4. **Legacy journals (no kdfIterations) don't prompt**: Fixed by using `LEGACY_KDF_ITERATIONS = 20_000` fallback.
5. **Unencrypted export of secure journal incorrectly requires password**: Split into `needsPassword` (required) and `canProvidePassword` (optional with Skip).
6. **Non-secure journal with encrypted attachments loses encryption on import**: Fixed by auto-deriving with empty password in import, preserving salt/kdfIterations for auto-derive, and adding readEncrypted fallback.
