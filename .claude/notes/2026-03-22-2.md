# v0.17.8 — Critical GDrive sync encryption (2026-03-22)

## Problem

All journal data synced to Google Drive was stored as plain text — including password-protected journals. The SyncEngine fully decrypted data locally before uploading raw JSON to GDrive.

## Solution

Encrypt all journal content at the SyncEngine level before upload, decrypt after download. Every journal gets a sync key derived from its salt. Password-protected journals use `PBKDF2(password, salt)`. Non-secure journals use `PBKDF2("", salt)` for passive scraping protection.

## Key changes

### Sync encryption (engine level)

- `SyncEngine.sync()` now requires a `syncKey: Uint8Array` for all journals
- Pages, metadata, and attachments are AES-256-GCM encrypted before upload
- Download path decrypts and gracefully skips corrupted/undecryptable pages

### Sync index

- New `index.json` per journal on GDrive: `{ [pageId]: { modified, deleted? } }`
- Stored unencrypted for O(1) timestamp comparison (avoids decrypting all pages per sync)
- Engine no longer eagerly fetches all remote pages — only changed ones

### RemoteStore interface

- `uploadJournalMeta/uploadPage` now accept opaque encrypted strings
- `downloadJournalMeta/downloadPage` return raw encrypted strings
- New `uploadSyncIndex/downloadSyncIndex` methods
- `DownloadResult` type removed (engine handles parsing)

### Data model

- `Journal.salt` is now required (was optional, only for secure journals)
- All journals get a salt at creation (already the case in `useCreateJournal`)
- Backup import generates salt for journals that lack one

### SyncManager key derivation

- When no derivedKey is provided, manager reads journal salt from local store and derives key via `PBKDF2("", salt)` — no more zero-key fallback

### Cloud import (NewJournalModal)

- Rewritten to decrypt downloaded data using salt-derived key
- Downloads pages individually via sync index instead of bulk fetch

### Documentation

- SECURITY.md: New "Google Drive Sync" section, updated backup section

- DATA.md: Updated GDrive filesystem structure (meta.json, index.json), salt now required
