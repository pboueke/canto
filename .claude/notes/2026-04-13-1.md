# v0.18.8 — Sync after password change, UI polish (2026-04-13)

## Problems

1. **Cloud import failed after password change** — re-encrypting locally (new salt → new key) didn't update page `modified` timestamps, so the sync engine's `localPage.modified === remoteEntry.modified` check skipped re-upload. GDrive registry got the new salt but pages stayed encrypted with the old key. Subsequent imports derived the new key from the new salt and failed to decrypt the old-key pages → "pages could not be downloaded".
2. **Cloud import dropped password protection** — `executeCloudImport` saved imported password-protected journals without the derived key, so pages were only device-encrypted locally even though the journal was marked `secure: true`.
3. **NewJournalModal was full-screen with white background on web** — slide-up animation with `flex: 1` container, no width constraint.
4. **Danger zone confirmation buttons had poor contrast** — `theme.colors.error` background with hardcoded `#fff` text failed WCAG AA on Nord, Everforest, Rosé Pine, One Cyan themes.
5. **Splash and Android adaptive icons were cropped** — logo extended too close to image edges, getting clipped by Android's adaptive icon safe-zone mask and looking tight on the splash screen.

## Solutions

### Sync engine: detect key change, force re-upload

`SyncEngine.sync()` now fetches the remote registry before processing pages and compares `remoteJournal.salt` with `localJournal.salt`. When they differ (only checked when both sides have a salt), `keyChanged = true` and all "both exist" pages are unconditionally re-encrypted and re-uploaded with the new key, bypassing the timestamp comparison.

### Cloud import: pass derivedKey to local store

`NewJournalModal.executeCloudImport` now computes `importKey = remote.encrypted && password ? syncKey : undefined` and passes it to both `saveJournal()` and `savePage()`, preserving password encryption locally.

### NewJournalModal styling: match dev menu

Modal switched from full-screen `slide` to `transparent` + `fade` with semi-transparent overlay (`rgba(0,0,0,0.5)`), centered floating container with `borderRadius: 5`, `maxHeight: 90%`, `webModalContent` (1000px max on web), background `theme.colors.foreground`, and themed border. Dropped `useSafeAreaInsets` since the modal no longer touches screen edges.

### Contrast utility for danger buttons

Added `getContrastText(bgColor)` to `themes.ts` — computes WCAG relative luminance and returns `'#fff'` or `'#000'` based on which gives higher contrast. Applied to `ConfirmDeleteModal` (delete button), `AccountButton` (account delete), and `FilterBar` (clear filters icon). All 10 themes now meet WCAG AA (≥3:1) on danger buttons.

### Icon padding (Pillow image regeneration)

- `assets/splash-icon.png`: 174×200 → 512×512 with logo centered (~170px padding each side)
- `assets/android-icon-foreground.png`: 1238×1372 → 1024×1024 with logo scaled to ~508×563 centered (well within Android's safe-zone)
- `assets/android-icon-monochrome.png`: same treatment as foreground
