# 2026-03-20 - Google Drive Sync on Web (Plan 14.2)

## What was done

Implemented full Google Drive sync support on the web platform. The sync engine, manager, and GDrive API layer already used plain `fetch()` and were platform-agnostic — only OAuth authentication was missing on web.

## Approach

- **Native auth untouched** — `GoogleAuthContext.tsx` continues using `@react-native-google-signin/google-signin`
- **Web auth via expo-auth-session** — `GoogleAuthContext.web.tsx` replaced no-op stub with real OAuth using `expo-auth-session/providers/google`
- **Implicit flow** — Google's web OAuth clients require a `client_secret` for authorization code flow, which is unsafe to embed in a SPA. Implicit flow returns access tokens directly without code exchange. Tradeoff: no refresh tokens (tokens expire in ~1 hour), but `getAccessToken()` attempts silent re-auth when expired
- **Token persistence** — stored in `localStorage` with configurable retention (1 day / 1 week / 1 month / never expire, default 1 week)

## Key decisions

1. **Why not GIS (Google Identity Services)?** Browser-only, no React Native webview support, no refresh tokens, tokens expire in 1 hour with no silent refresh
2. **Why not replace native auth with expo-auth-session?** Native auth works perfectly, replacing it risks mobile regressions for zero benefit
3. **Why implicit flow over authorization code flow?** Google requires `client_secret` for code exchange on web clients. Embedding secrets in SPAs is insecure. Implicit flow avoids this entirely

## GCP Console requirements

The web OAuth client needs **Authorized JavaScript Origins** and **Authorized Redirect URIs** configured (e.g., `http://localhost:8081` for dev). See updated note `2026-03-17-6.md` section 4a.

## Additional fixes (web bugs found during testing)

- **Biometric gate on web** — `authenticateBiometric()` returns `false` on web, which silently blocked access to biometric-locked journals. Fixed by skipping biometric gate on web (`Platform.OS !== 'web'`), falling through to password prompt
- **DevMenu buttons on web** — `Alert.alert()` with callback-based buttons doesn't work on react-native-web. Fixed by using `window.alert()` / `window.confirm()` on web
- **ConfirmDeleteModal text node warning** — `deleteError` initialized as `''` caused `{'' && <Text>}` to emit a bare text node in react-native-web. Fixed by using `null` instead of empty string and explicit ternary
