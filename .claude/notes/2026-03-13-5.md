# v0.8.2 continued — UX fixes, KDF improvements, biometric security fix

## KDF iteration picker improvements

- Renamed `standard` preset label to `improved` across all 8 languages
- Changed `DEFAULT_KDF_ITERATIONS` from 100k to 50k (`fast` is now default)
- Updated `kdfExplainBody` in all 8 languages to include actual iteration values per preset
- Moved KDF explanation from inline hint to `?` modal (help-circle button next to Key Strength label)

## Password explanation modal

- Added `?` help button next to "Optional" password label in `NewJournalModal`
- Opens modal explaining how Canto uses device-level encryption + optional password layer
- Added `passwordExplainTitle` and `passwordExplainBody` i18n strings in all 8 languages
- Shortened `passwordOptional` label to just the translated word "Optional" (no trailing hint text)

## Bug fixes

### Silent journal creation failure (Android)

- Root cause: `File.move()` on Android throws `FileAlreadyExistsException` when target exists
- Fix: added `moveFile()` helper in `local.ts` that deletes target before move, applied to all 6 `move()` call sites
- Added error display box to `NewJournalModal` (was silently swallowing errors)

### No loading spinner during journal operations

- Added loading `<Modal>` in `NewJournalModal` during creation (replaced plain View overlay)
- Added loading `<Modal>` in `app/index.tsx` for non-password journal unlock
- Used `await new Promise(r => setTimeout(r, 100))` to yield before async work so React renders the spinner

### Password change: current password never verified

- `deriveAndCache()` uses PBKDF2 which always succeeds regardless of password
- Fix: added trial decryption via `tryLoadJournal()` after deriving key to actually verify the password
- On wrong password, restores correct cached key so journal remains accessible

### Biometric bypassing password prompt (security fix)

- **Problem**: biometric-enabled journals with passwords could be opened via biometric key retrieval alone, bypassing the password prompt entirely
- **Fix**: biometric is now strictly an additional authentication gate, never a password replacement
- Removed `getBiometricKey()` usage from `handleJournalPress` in `app/index.tsx`
- Removed `storeBiometricKey()`/`clearBiometricKey()` from password change and biometric toggle in `JournalSettings.tsx`
- New flow: biometric + password → biometric prompt first (gate) → then password modal (always required)
