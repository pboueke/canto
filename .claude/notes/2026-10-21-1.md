# 21 — Lock-screen privacy and device-key integrity (v0.21.0)

Plan: `.claude/plans/21.lock-privacy-and-key-integrity.md`. Branch: `feature/0.21.0-lock-privacy-key-integrity`.

This release came from two user reports, with no requirement file:

- **Typed text on lock.** Text typed in the editor stayed visible behind the auto-lock password prompt.
- **Journal lockout.** A user affected by the 0.19.2 → 0.20.2 page-loss incident could no longer open her journal after rotating the device key.

## Root causes

### Lock privacy

- `AutoLockModal` was a translucent `Modal` with a 50% overlay. The editor, journal list and calendar stayed mounted underneath and kept rendering their decrypted state.
- Dismissing the lock used `router.replace('/')`. A dirty editor's `beforeRemove` guard could cancel it, and "Keep" left plaintext on screen in an editor that could no longer save or unlock.
- The lock decision ran only after the app was active again, behind an `await`, so the editor painted first.
- Nothing hid content from the app switcher.

### Journal lockout

- **Zero-key records (most likely cause).** In 0.20.0 and earlier, an editor still open after an auto-lock saved pages and catalogs with the zeroed key buffer, so their password layer was 32 zero bytes.
  - The fail-closed reader added in 0.20.1 rejects those records with `CATALOG_UNREADABLE`.
  - `handleUnlock` reported every error as "Wrong password", including this one when the password was correct.
  - Rotation neither caused nor fixed this state.
- **Rotation abort (destructive).** If applying the rotation failed after its commit point, the UI aborted the key cutover. That deleted the only key that could read the already-published new ciphertext, and startup then replayed the transaction under the lost key.
- **Secondary rotation bugs.**
  - Unindexed journal directories stayed on the retired key.
  - Writes queued behind the rotation ran with the stale cached key.

## What landed

### Part A — privacy

- **Opaque lock.** `AutoLockModal` is a full-screen opaque `Modal`. Dismissing it runs `dismissAll()` and then `replace('/')`.
- **Privacy cover.** `PrivacyCover` is a top-level opaque `Modal`, shown while the app is not active and on resume until the lock decision completes. It is driven by `JournalKeyContext.isPrivacyCovered` / `subscribePrivacyCover`, with a resume generation counter.
- **Pre-lock flush.** `JournalKeyContext.onBeforeLock` lets the editor flush its draft after the lock screen shows and before keys are zeroed. The flush is bounded by `BEFORE_LOCK_TIMEOUT_MS` (3 s).
- **Editor.**
  - It locks on `onAutoLock` and on `onJournalLocked`, then shows `LockedPlaceholder` and drops decrypted state.
  - Discard guards and stale prompts do nothing while locked.
  - Drafts flush on background, before a lock, and after 3 s idle.
  - A stored draft is restored with an "Unsaved changes restored" banner and a Discard action.
  - Save and delete check `isLeaseValid` at call time, which fixes the stale-closure re-check.
- **Journal and calendar screens** show the placeholder after a lock. The journal screen lists "Unsaved draft" rows.
- **Decrypted state in hooks.** `usePage` / `useJournalOverview` expose a value only under the key it was read with, and free it from memory once the key is lost.
- **Encrypted drafts** (`saveDraft` / `getDraft` / `listDrafts` / `deleteDraft`).
  - Storage: native `<journal>/drafts/`, web `canto/<journal>/drafts/`.
  - Exclusions: drafts are not part of the catalog, recovery, export, sync or import.
  - Lifecycle:
    - removed with their page or journal;
    - rotated with the device key;
    - password change refuses while drafts exist (`DraftsPendingError`).
- **Android app switcher.** The `plugins/withAndroidRecentsPrivacy.js` config plugin calls `setRecentsScreenshotEnabled(false)` on API 33+.
- **`expo-screen-capture`.**
  - Provides an opt-in "Block screenshots" setting (`src/lib/privacy.ts`), which uses `FLAG_SECURE` on Android.
  - Enables the iOS app-switcher blur at startup.
  - Its unused `READ_MEDIA_IMAGES` and `DETECT_SCREEN_CAPTURE` permissions are blocked in `app.json`.

### Part B — key integrity

- **`src/lib/storage/device-key-rotation.ts`.** `runDeviceKeyRotation` owns the commit point.
  - Before it, any failure discards the staging copy and restores the old key.
  - After it, a failure keeps both keys, seals writes until restart (`RotationInterruptedError`), and lets startup finish the job.
- **Rotation steps.** Each store's `rotateDeviceKey()` runs inside the write barrier and swaps the cached device key before queued writers resume.
  - Preflight refuses for: unindexed journal data, pending imports or transactions, a pending fallback key, oversized legacy attachments, too little free space, or an unreadable index. It also clears a stale completion marker.
  - Verify checks that every target matches its staged copy, and trial-decrypts the index, metadata, catalogs and up to 10 pages per journal with the new key.
- **Startup.** `ensureInitialized` clears the cached device key after rotation recovery. This fixes a stale-key read after a rollback.
- **`src/lib/storage/key-integrity.ts`:**
  - legacy zero-key classification;
  - strict `verifyJournalKey`, returning `valid`, `invalid` or `unverifiable`;
  - counts-only `collectDiagnostics`.
- **`LEGACY_ZERO_KEY`.** Overview reads report it. `scanJournalPages` counts legacy pages. `restoreJournalCatalog` re-encrypts legacy pages, metadata and zero-key attachment payloads in one transaction, and only with a verified key; otherwise it fails with `KEY_UNVERIFIABLE` or `JOURNAL_LOCKED`.
- **Typed metadata error.** Metadata that does not open now throws `JOURNAL_UNREADABLE` (`PASSWORD_DECRYPT_FAILED`).
- **Home unlock.**
  - It uses `verifyJournalKey`, so only `invalid` shows "Wrong password".
  - Integrity errors clear the key and open the journal screen, which shows `JournalIntegrityPanel` (recover pages / copy diagnostics / back).
  - A wrong password now rejects `onUnlock`, so the unlock rate limiter counts the attempt. Before, every attempt reset the limiter.
- **Change password.** It verifies the current password with an uncached, zeroed trial key, so a wrong entry no longer replaces the working key.
- **Hardening.**
  - Native record ids are validated before use as path segments (`safeRecordId`).
  - Native transaction cleanup deletes the marker before the staged files (`retireTransaction`).
- **Diagnostics.** "Copy diagnostics" appears on the integrity panel and on the home recovery card. The report contains the app build, the integrity code, key-custody state and storage counts, and no content, ids, paths or keys.

### Other

- **Strings.** 25 new strings across 20 languages.
- **Versions.** 0.21.0, Android versionCode 31. The dependency manifest is regenerated for `expo-screen-capture`.

## Found in web testing (2026-10-21)

**Regression: reloading a page on web showed a blank editor, and the journal then showed "needs attention".**

- **Cause.** Reloading clears unlocked keys from memory. The new typed metadata error (`JOURNAL_UNREADABLE` / `PASSWORD_DECRYPT_FAILED`) made a keyless, locked journal look damaged. Before this release, that state sent the user home to unlock. The data itself was intact: every record showed a working device layer and an unopened password layer.
- **Fixes.**
  - The journal screen treats a password-layer failure (or `LEGACY_ZERO_KEY`) with no key in memory as locked and goes home to unlock. The integrity panel is now shown only after a verified unlock, or for damage that needs no key.
  - The editor shows `LockedPlaceholder` when it has no key and the page does not open.
  - Diagnostics count keyless password-layered records as `notOpenedWithoutKey` rather than `undecryptable`.
- **Tests.** Journal screen, editor, diagnostics, and a reload step in `lock-privacy-e2e`. Full suite after the fixes: 126 suites, 1,887 tests. Coverage was unchanged on statements (98.93%), functions (98.51%) and lines (99.54%); branches rose from 95.85% to 95.88%.

## Adversarial reviews (2026-10-21)

Two independent adversarial reviews ran, one for data loss and one for cross-platform behaviour. Each finding was fixed with a regression test, or left with the reason noted.

**Data loss**

- **Failed rotation rollback (high).** After the commit-marker write failed, a failed rollback left writes unsealed under a cached new key that the next startup discarded. Now the cached key switches only after the commit point, and a failed rollback seals writes.
- **Restored draft versus newer page.** A draft older than the saved page (after a sync, a remote delete, or a failed cleanup) asks "Use my draft" or "Keep saved version". Discarding marks the draft unsaved at once, which closes the save-after-discard race. The banner's "Discard draft" asks for confirmation.
- **Sync deletions.** A storage `deletePage` no longer deletes the draft, so a deletion synced from another device keeps local unsaved typing. The journal list shows drafts of deleted pages, and only a delete made in the editor discards a draft.
- **Lock-time draft save.** The save uses a private copy of the key, wiped afterwards, so a save queued past the 3 s lock window still succeeds.
- **Transaction cleanup.** A cleanup failure after the data is applied no longer fails the save. An unremovable marker is rewritten as `retired`, so startup neither replays it over newer saves nor rolls back attachment roots it published. Removing superseded attachment roots after a password change is best effort.
- **Unconfirmable passwords.** A password returning `unverifiable` opens the journal read-only (`markReadOnly`), so nothing is written under a possibly mistyped key.
- **Web journal delete.** It now uses a trailing slash in the prefix. Import markers with unusable ids are skipped instead of failing every startup.

**Cross-platform**

- **iOS modal stacking.** iOS presents one modal per presenter, so the separate cover and lock modals could drop the lock screen. The cover is now a plain `PrivacyShield` view at the root, and the lock screen is the only top-level `Modal`; its state lives in the key context. This also fixes the camera and permission-prompt conflict.
- **Content modals.** A shield sits inside every content modal, covering it while the app is inactive, backgrounded or locked. The native image viewer closes instead.
- **Web multiple tabs.**
  - Each tab holds a shared Web Lock.
  - Rotation refuses while another tab is open (`OTHER_TABS_OPEN`).
  - Startup recovery waits on the rotation lock.
  - Node's own process-wide `navigator.locks` is disabled in the Jest setup.
- **Copy diagnostics.**
  - The copy starts inside the tap: on web, a `ClipboardItem` receives a promise of the report.
  - The result is checked, and the report is shown as selectable text when copying fails.
  - Web diagnostics report the user agent.
- **Android 12 and below.** The recents plugin also holds `FLAG_SECURE` while paused, without undoing the user's "Block screenshots" setting.
- **Web reloads.** The editor warns before a reload or tab close while edits are unsaved.
- **Web dialogs.** `src/lib/dialogs.ts` replaces button `Alert`s (a no-op on react-native-web) in the editor, Security settings, the journal screen and the location tag.
- **Locked screen.** It has a "Back to journals" button.
- **Not changed:**
  - Brief cover flashes around system flows on Android (pickers) and iOS (Face ID).
  - The Security settings modal stays capturable until it is reopened after turning on "Block screenshots".
  - iOS diagnostics have no build number, because `app.json` sets none.

**Strings and verification**

- 6 new strings in 20 languages: draft conflict ×4, rotation with other tabs open, and manual diagnostics copy.

## Found in Android device testing (2026-10-21): rotation skipped every journal record

**Symptom.** After "Rotate device key" on a real Android device, every journal showed "This journal needs attention", with `record:… unreadable (DEVICE_DECRYPT_FAILED)` in the logs.

**Cause.** This bug predates this branch: the same line is in v0.19.2 and v0.20.x.

- expo-file-system on Android reports directory uris with a trailing `/` (`FileSystemDirectory.asString()`).
- `reencryptAll` built each journal's prefix as `${dir.uri}/`, i.e. `…/journalId//`, which matches no file.
- Rotation therefore re-encrypted only `journals.json`, committed, and deleted the old key that every journal record still needed.
- The Jest mocks built directory uris without the trailing slash, so no test caught it.

**This most likely explains the reporter's lockout.** On Android, any rotation in 0.19.2–0.20.2 left all journal data under a deleted key. The data cannot be recovered on the device; only a Google Drive sync or a `.canto.zip` export can restore it. Her diagnostics would show `metadata`/`pages` `deviceFailed` counts.

**Fixes.**

- `childPrefix()` builds directory prefixes without doubling the slash. It is also used for the chunk-root check in `reencryptJournal`.
- Backstop on native and web: staging refuses to commit unless every indexed journal's metadata record was staged. A future enumeration bug now blocks the rotation with `UNREADABLE_DATA` and changes nothing.
- The rotation test's expo-file-system mock now reproduces Android's uris (trailing slash, no double slashes). With that mock, 18 rotation tests failed before the fix and all pass after it.
- New regression tests for the backstop, native and web.

**Fixed:**

**Observed, not changed:**

## Known gaps

- **Orphaned journal directories** block rotation, and no flow recovers them yet. They show in diagnostics as `unindexedJournalDirectories`.
- **Genuinely corrupt pages** still block recovery; only zero-key pages are recoverable.
- **Drafts on other pages.** A draft whose page was deleted elsewhere (for example by sync) stays on disk without a row in the journal list.
- **Android below 13.** Check on device whether `FLAG_SECURE` also covers React Native `Modal` windows.

## User follow-up (affected reporter)

- **Don't:** reinstall, clear app data, rotate again, or edit until 0.21.0 is installed.
- **Then:** unlock with her password. With zero-key pages, the journal opens on the integrity panel, and "Recover pages" re-encrypts them.
- **If it still fails:** ask her for the "Copy diagnostics" output and her versionCode.
