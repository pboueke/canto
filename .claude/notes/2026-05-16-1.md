# 19.1 — Release Fixes (v0.19.1)

Five UX/robustness fixes shipped together. Plan: `.claude/plans/19.1.release-fixes.md`.

## What landed

### Issue 1 — Font customization in style picker

- New module `src/lib/font.ts` — `FONT_SCALES`, `getFontFamilies`, `applyFontPrefs`, `scaleFont`.
- New context `src/contexts/FontPrefsContext.ts` + `useFontPrefs()` hook.
- `app/_layout.tsx` — loads OpenDyslexic (.otf) and Lora (.ttf) fonts; persists `canto:fontSize` / `canto:fontFamily` in AsyncStorage; wraps app in `FontPrefsContext.Provider`; applies font prefs to the theme via `applyFontPrefs` before passing to `ThemeContext`.
- `src/styles/themes.ts` — `CantoTheme.fonts` now includes `fontScale: number` (default 1.0 on all 10 themes).
- `src/components/home/ThemePickerModal.tsx` — adds two new rows (Font size, Font family) above the theme grid; whole modal wrapped in a `ScrollView` to keep it usable with the new sections; font controls hidden when modal is used as a per-journal override picker (`showGlobalOption=true`).
- `src/components/home/InfoBox.tsx` — row label switched from `t.settings.theme` to `t.settings.appearance`.
- `src/components/page/PageContent.tsx` — applies `theme.fonts.fontScale` to all editor + markdown sizes/line-heights. This is the primary reading surface; font scaling is intentionally NOT applied to navigation/chrome UI for this release.

**Scope trade-off**: font scaling currently affects the journal page editor + rendered markdown. Other UI surfaces (chrome, lists, modals) use literal `fontSize` values and don't scale — would require touching ~45 files. Tracked as a follow-up for 19.2.

### Issue 2 — Decryption modal copy

- `src/components/home/JournalAccessModal.tsx:102` — `t.common.loading` → `t.home.decrypting`.
- New `t.home.decrypting` key added with translations from each locale's existing `t.page.decrypting` value (no new translation work — strings already existed for the page-level use).

### Issue 3 — GDrive preparing-import state

- `src/components/home/NewJournalModal.tsx` — new `cloudImportPhase: 'idle' | 'preparing' | 'downloading'` state alongside (not replacing) the existing `importing` boolean for local ZIP imports.
- `executeCloudImport` sets phase to `'preparing'` at start (covers connect + downloadMeta + key derivation + downloadSyncIndex), then `'downloading'` when the per-page loop begins.
- Busy view renders `t.sync.preparingImport` during `'preparing'` (no progress bar), and `t.backup.importing` + progress bar during `'downloading'`.
- New `t.sync.preparingImport` key with translations for all 20 locales.

### Issue 4 — Per-page retry on cloud import

- New `src/lib/sync/retry.ts` — `retryWithBackoff` utility (5 tests, all passing).
- `executeCloudImport` per-page loop now wraps the page-download pipeline (download + decrypt + attachments) in `retryWithBackoff` with 5 attempts and `1s/2s/4s/8s` exponential backoff. Failures after all 5 attempts get recorded into the existing `downloadFailures` array → existing integrity-warning UI surfaces them.
- API-level `fetchWithRetry` in `src/lib/sync/gdrive/api.ts` left unchanged — it handles transport-layer transient errors; the new layer handles full-page-import retries.

### Issue 5 — Keyboard covers last line in editor

- `app/page/[id].tsx` — `ScrollView` wrapped in `KeyboardAvoidingView` (iOS=padding, Android=height, `keyboardVerticalOffset={insets.top + 60}`). `scrollViewRef` passed to `<PageContent>` via new `onCursorMove` prop that calls `scrollToEnd({ animated: false })`.
- `src/components/page/PageContent.tsx` — `onSelectionChange` + `onContentSizeChange` both trigger `onCursorMove`. `minHeight: 400` removed from container (TextInput auto-grows naturally).
- `android:windowSoftInputMode="adjustResize"` already present in `AndroidManifest.xml` — no change needed.

## Scope deviations from plan

1. **`cloudImportPhase` parallel to `importing`** instead of fully replacing `importing`. The `importing` boolean is also used by local ZIP import handlers (`handleImport`, `handleImportPasswordSubmit`, `finishImport`); replacing it would have required refactoring 4 unrelated flows. Two-state approach keeps the cloud path clean without regressing local imports.
2. **Font scaling does NOT apply app-wide**, only to PageContent + markdown. Documented above. Tracking expansion as 19.2.
3. **No dedicated `NewJournalModal.retry.test.tsx`** — the retry utility is well-tested at the unit level, and the modal's setup overhead would have been disproportionate. The plan's other tests covered the integration assertions.
