# Encrypted Backup Fix — v0.9.1

Fix for encrypted export/import flow discovered during QA of v0.9.0 backup feature.

---

## Root Cause

JSZip's compress/decompress cycle on Hermes (React Native's JS engine) corrupts base64 strings stored as text entries in the ZIP. The corruption introduced non-base64 characters, causing `atob()` to reject the string on import. Stripping invalid characters let the decode succeed but produced wrong bytes, leading to AES-GCM authentication failure ("invalid ghash tag").

## Fix

Encrypted ZIP entries are now stored as raw binary (`Uint8Array`) instead of base64 strings, completely bypassing string encoding and JSZip's text compression path.

### Changes

1. **`src/lib/encryption/utils.ts`**
   - Added `aesGcmEncryptBytes()` / `aesGcmDecryptBytes()` — binary variants that return/accept `Uint8Array` directly (no base64 intermediate)
   - Replaced `atob`/`btoa`-based `base64ToUint8`/`uint8ToBase64` with pure-JS lookup-table implementations (robust on Hermes)
   - Exported `base64ToUint8` and `uint8ToBase64` for use by other modules

2. **`src/lib/backup/export.ts`** — Uses `aesGcmEncryptBytes` for encrypted entries → JSZip stores as binary natively

3. **`src/lib/backup/import.ts`** — Reads encrypted entries with `async('uint8array')` + `aesGcmDecryptBytes` instead of `async('string')` + `aesGcmDecrypt`. Consolidated duplicate `base64ToUint8` — now imported from `utils.ts`.

4. **`src/components/home/NewJournalModal.tsx`** — Removed duplicate `base64ToUint8`, imports from `utils.ts`

5. **`src/lib/storage/local.ts`** — Added try/catch fallback to `getAttachment` (matching existing `readEncrypted` pattern) for cases where an attachment's `encrypted` flag doesn't match its actual encryption state on disk

6. **`src/lib/__tests__/backup.test.ts`** — Updated encrypted test helpers to use binary variants

## Key Design Decision

The ZIP format for encrypted backups changed: encrypted entries are now binary blobs instead of base64 text. This is a breaking change for ZIPs exported with v0.9.0, but since the feature was broken on device (the bug this fixes), no valid encrypted ZIPs exist in the wild.
