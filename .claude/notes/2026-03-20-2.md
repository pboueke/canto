# v0.14.3 — Cross-platform sync e2e tests, timestamp fix, web navigation fix

## savePage() timestamp mutation bug (critical)

Both `local.ts` and `local.web.ts` unconditionally overwrote `page.modified` with `Date.now()` in `savePage()`. This broke sync in two ways:

1. **Sync download path**: When SyncEngine downloaded a remote page and saved it locally, the remote timestamp was destroyed. On the next sync, the page appeared "locally newer" and got re-uploaded, overwriting any remote changes.
2. **Cloud import path**: `NewJournalModal.handleCloudJournalSelect()` called `savePage()` for every imported page, replacing all timestamps with the import time. Auto-sync then re-uploaded every page.

**Fix**: Added `preserveModified?: boolean` parameter to `LocalStore.savePage()`. SyncEngine passes `true` when saving downloaded pages. Cloud import passes `true` when saving imported pages.

Files changed:

- `src/lib/storage/types.ts` — interface updated
- `src/lib/storage/local.ts` — native implementation
- `src/lib/storage/local.web.ts` — web implementation
- `src/lib/sync/engine.ts` — passes `preserveModified: true` on download
- `src/components/home/NewJournalModal.tsx` — passes `preserveModified: true` on import

## Cross-platform sync e2e test suites (46 new tests)

### Web e2e sync tests (`gdrive-sync-e2e-web.test.ts` — 21 tests)

Mirrors native e2e with real web storage behavior via InMemoryLocalStore. Adds: timestamp preservation, re-sync idempotency, settings round-trip, soft-delete persistence, multi-journal isolation, import regression guards.

### Cross-platform sync tests (`cross-platform-sync-e2e.test.ts` — 23 tests)

Two InMemoryLocalStore instances (native + web) syncing through same InMemoryDrive:

- Native→Web (6): page sync, attachments, mixed states, metadata, encrypted journals, sequential edits
- Web→Native (4): page sync, attachments, encryption, deletion
- Bidirectional (7): concurrent edits, conflict resolution, edit chains, delete-vs-edit, attachment survival
- Edge cases (6): empty journals, empty/unicode/large text, idempotent rapid syncs, settings propagation

### Known limitation documented

Cross-device deletion propagation: current design trashes the remote file (invisible to other devices), so the other device re-uploads the page. Tests document this behavior.

## Web navigation fix (GO_BACK not handled)

After refreshing a journal or page URL on web, the navigation stack is empty. `router.back()` fails with "The action 'GO_BACK' was not handled by any navigator."

**Fix**: Created `useSafeBack` hook that checks `canGoBack()` and falls back to `router.replace('/')`. Applied to:

- `src/components/common/BackButton.tsx`
- `app/page/[id].tsx` (4 call sites)

Added `testPathIgnorePatterns: ['/__tests__/helpers/']` to prevent helper files from being picked up as test suites.
