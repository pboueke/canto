## Bugfixes in `src/lib/backup/import.ts`

1. **Relaxed attachment ID regex** (line 172): `[a-f0-9-]+` → `[^.]+` — prevents silent attachment loss for non-hex IDs.

2. **Auto-derive no longer marks journal secure** (line 246): Added `hasUserProvidedKey` flag. `preservePassword` now only true when user explicitly provides a key. Prevents phantom password prompt on import without key.

3. **Shared attachments get per-page copies** (lines 177-214): Each owning page gets its own copy under its directory. Prevents orphaned attachments when one page is deleted. Path map keyed by `pageId:zipFilename`.

4. **Step-level error logging**: `console.error` now identifies which specific file failed to decrypt (journal metadata, settings, page, or attachment).

## Fix in `src/lib/backup/export.ts`

**Disabled compression for encrypted entries**: Added `compression: 'STORE'` for all encrypted ZIP entries. Encrypted data is incompressible and the deflate/inflate cycle was the likely cause of `aes/gcm: invalid ghash tag` errors on Hermes. This is the same class of bug v0.9.1 partially addressed (switching to Uint8Array) — compression remained as a corruption vector.
