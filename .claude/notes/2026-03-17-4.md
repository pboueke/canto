# 9.4 Native Crypto via expo-crypto + Image Loading Optimization

## What changed

### Expo SDK upgrade (54 → 55)

- React 19.1 → 19.2, React Native 0.81 → 0.83
- No breaking changes affected this project (no usage of removed APIs)
- expo-doctor: 17/17 checks passed

### AES-GCM crypto backend: @noble/ciphers → expo-crypto

- `aesGcmEncrypt`, `aesGcmDecrypt`, `aesGcmEncryptBytes`, `aesGcmDecryptBytes` are now async
- Backed by `expo-crypto`'s native AES-GCM (OpenSSL on Android, CommonCrypto on iOS)
- Wire format unchanged: `[12-byte IV][ciphertext][16-byte GCM tag]` — backward compatible with existing encrypted data
- `@noble/ciphers` moved to devDependency (used only in Jest mock for expo-crypto)
- `bytesToHex`/`hexToBytes` moved from `@noble/ciphers/utils.js` to local helpers in `device.ts`

### Files modified

- `src/lib/encryption/utils.ts` — core crypto functions now use expo-crypto
- `src/lib/encryption/device.ts` — local hex helpers, await crypto calls
- `src/lib/encryption/password.ts` — await crypto calls
- `src/lib/storage/local.ts` — 5 call sites updated to await
- `src/components/home/SecuritySettingsModal.tsx` — removed Promise.resolve wrappers
- `src/lib/backup/export.ts` — extracted inline calls to awaited variables
- `src/lib/backup/import.ts` — await crypto calls
- `jest.setup.ts` — expo-crypto Jest mock delegating to @noble/ciphers
- `jest.config.js` — added expo-crypto to transformIgnorePatterns

### Image loading: data URIs → file URIs

- Decrypted images now written to temp files in `Paths.cache` instead of passed as `data:image/jpeg;base64,...` URIs
- Eliminates multi-megabyte strings in React state and React reconciliation diffing
- `PageListItem.tsx` thumbnails also use file URIs

### JS thread yield strategy

- Added `setTimeout(0)` yields in `aesGcmDecrypt`/`aesGcmEncrypt` before heavy synchronous operations (`base64ToUint8`, `textDecoder.decode`)
- Added yield before synchronous `file.write()` in image load callbacks
- Reduced `MAX_CONCURRENT` from 2 to 1 — single pipeline avoids doubled blocking
- Batched `setLoadedImages` + `setLoadingImages` state updates to reduce re-renders

## Key decisions

- expo-crypto chosen over react-native-quick-crypto to preserve Expo Go compatibility
- @noble/ciphers kept as devDependency for Jest mock (expo-crypto needs native runtime)
- Yields added in crypto layer rather than only in image path — benefits all large-payload decryption
