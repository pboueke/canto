# Bugfix 0.8.1: Always derive encryption key

**Date:** 2026-03-13

## Problem

When a user created a journal without setting a password, no salt was generated and no PBKDF2 key was derived. Data was stored with only device-level AES-256-GCM encryption — missing the password-layer encryption entirely.

## Changes

### `src/hooks/useStorage.ts` — useCreateJournal

- Always generate salt and derive key using `password || ''` (empty string as fallback)
- `secure` flag unchanged — still means "user set a password" for UI purposes

### `app/index.tsx` — Home screen

- Always pass `deriveAndCache` to `create` (not just when password is set)
- Auto-derive empty-string key for non-secure journals on access (new `else if` branch in `handleJournalPress`)

### `app/journal/[id].tsx` — Journal screen

- Added safety-net `useEffect` to auto-derive key if journal has salt but no cached key (covers deep link navigation)

### `src/components/home/NewJournalCard.tsx`

- Fixed card height from 120 to 130 to match JournalCard dimensions

## Backward compatibility

Existing journals created before this fix have no salt — `readEncrypted` handles `derivedKey === undefined` gracefully (skips password layer). No migration needed.
