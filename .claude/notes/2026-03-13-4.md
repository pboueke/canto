# Security Hardening v0.8.2

Implementation of plan `.claude/plans/8.2.security-hardening.md`.

## Changes by issue

### Issue 1: User-selectable PBKDF2 iterations

- Added `kdfIterations?: number` to `Journal` and `JournalContent` models
- Removed hardcoded `PBKDF2_ITERATIONS` constant from `password.ts` and `JournalKeyContext.tsx`
- `deriveKey()` now requires explicit iterations parameter
- Exported `LEGACY_KDF_ITERATIONS` (20k), `DEFAULT_KDF_ITERATIONS` (200k), and `KDF_PRESETS` from `password.ts`
- `deriveAndCache()` in `JournalKeyContext` now accepts optional `iterations` parameter (defaults to 20k for backward compat)
- Created `KdfIterationPicker` component — segmented pill selector with 4 presets
- Added picker to `NewJournalModal` and `ChangePasswordModal` (shown when password field is non-empty)
- All call sites updated to pass `journal.kdfIterations` when deriving keys
- `kdfIterations` stored in journal index and metadata

### Issue 2: Device key rotation

- Added `rotateKey()` to `device.ts` — generates new key, stores in SecureStore, returns old+new
- Added `reencryptAll()` to `LocalStore` — re-encrypts all journals, pages, attachments with new device key
- Device key rotation exposed via Security Settings modal with confirmation dialog

### Issue 3: Persistent rate limiter

- Rewrote `ratelimit.ts` to use AsyncStorage persistence
- All methods now async (`attempt()`, `reset()`, `lockoutRemaining()`)
- Escalating lockout: 30s after 5 attempts, 5min after 10, 30min after 15
- Updated `JournalAccessModal` for async rate limiter
- Updated tests to handle async API

### Issue 4: Session timeout / auto-lock

- Added `touchActivity()` to `JournalKeyContext`
- AppState listener clears all keys when app returns from background after timeout
- 30-second periodic check clears keys on foreground inactivity
- Auto-lock timeout configurable (1m/5m/15m/off) in SecuritySettingsModal, stored in AsyncStorage

### Issue 5: Biometric key storage

- Added `storeBiometricKey()`, `getBiometricKey()`, `clearBiometricKey()` to `biometric.ts`
- Uses SecureStore with `requireAuthentication: true` for native biometric protection
- On journal access: attempts biometric key retrieval before showing password modal
- Biometric toggle stores/clears key; password change refreshes stored key
- Added `setKey()` to `JournalKeyContext` for direct key injection from biometric retrieval

### Issue 6: JS memory limitations

- Added documentation comments in `password.ts` and `JournalKeyContext.tsx`

### Issue 7: Index integrity verification

- Wrapped `readEncrypted` in try/catch — returns null on decryption failure instead of crashing
- Logs warning via `console.warn` for debugging

### Issue 8: Atomic password re-encryption

- Added `atomicWrite()` helper — writes to .tmp file, then renames to final
- Added `reencryptJournal()` to LocalStore — atomic re-encryption per journal
- Added crash recovery in `initialize()` — detects .tmp files and completes interrupted swaps
- `handleChangePassword` now uses atomic `reencryptJournal` instead of `saveJournal`

### Global security settings

- Created `SecuritySettingsModal` component
- Added "Security" row to `InfoBox`
- Auto-lock timeout picker and device key rotation button

### i18n

- Added `security` section to Dictionary type and all 8 languages
