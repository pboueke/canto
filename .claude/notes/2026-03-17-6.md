# 2026-03-17 - Google Cloud Project Setup Guide (Requirement 11)

No Expo account required — uses native deep-link redirect via the app's `scheme: "canto"` (already configured in `app.json`).

## 1. Create a Google Cloud Project

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Click **Select a project** → **New Project**
3. Name it (e.g., `canto-journal`) and click **Create**

## 2. Enable the Google Drive API

1. In the project dashboard, go to **APIs & Services** → **Library**
2. Search for **Google Drive API** and click **Enable**

## 3. Configure OAuth Consent Screen

1. Go to **APIs & Services** → **OAuth consent screen**
2. Select **External** user type (unless you have a Google Workspace org)
3. Fill in:
   - **App name**: Canto
   - **User support email**: your email
   - **Developer contact**: your email
4. Click **Save and Continue**
5. On the **Scopes** step, click **Add or Remove Scopes** and add:
   - `https://www.googleapis.com/auth/drive.appdata`
   - `https://www.googleapis.com/auth/drive.file`
6. Save and continue through the remaining steps
7. Under **Test users**, add your Google account email(s)

> **Note**: While in "Testing" mode, only listed test users can authenticate. To allow any Google user, you'll need to publish the app and go through Google's verification process.

## 4. Create OAuth Credentials

You need **three** OAuth client IDs (one per platform). No Expo proxy is used.

### 4a. Web client ID (required for token exchange)

1. Go to **APIs & Services** → **Credentials**
2. Click **Create Credentials** → **OAuth client ID**
3. Select **Web application**
4. Name it (e.g., `Canto Web`)
5. **Authorized redirect URIs**: leave empty (only used for server-side token exchange by expo-auth-session, no actual web redirect needed)
6. Click **Create** and note the **Client ID**

### 4b. Android client ID

1. Click **Create Credentials** → **OAuth client ID**
2. Select **Android**
3. **Package name**: `com.canto.app`
4. **SHA-1 fingerprint**:
   - For debug: `keytool -keystore ~/.android/debug.keystore -list -v` (password: `android`)
   - For release: use your release keystore
5. Click **Create** and note the **Client ID**

### 4c. iOS client ID

1. Click **Create Credentials** → **OAuth client ID**
2. Select **iOS**
3. **Bundle ID**: `com.canto.app`
4. Click **Create** and note the **Client ID**

## 5. Store Credentials in the Project

A template file already exists at the project root: `google-credentials.ts` (gitignored).

Replace the `REPLACE_ME` placeholders with your actual client IDs:

```typescript
export const GOOGLE_CREDENTIALS = {
  webClientId: '<your-web-client-id>.apps.googleusercontent.com',
  androidClientId: '<your-android-client-id>.apps.googleusercontent.com',
  iosClientId: '<your-ios-client-id>.apps.googleusercontent.com',
};
```

## 6. How Authentication Works (no Expo account)

The app uses `expo-auth-session` in **proxy-free mode**:

```typescript
import * as AuthSession from 'expo-auth-session';

const redirectUri = AuthSession.makeRedirectUri({ scheme: 'canto' });
// Produces: canto:// (native deep link)
```

- On **Android/iOS**: the OS handles the `canto://` redirect back to the app after Google sign-in
- The **web client ID** is passed as the `clientId` for the authorization code exchange
- The **platform-specific client ID** is passed via `androidClientId` / `iosClientId`
- Refresh tokens are stored in `expo-secure-store` for session persistence

## 7. Scopes Summary

| Scope           | Purpose                                                     |
| --------------- | ----------------------------------------------------------- |
| `drive.appdata` | Read/write to app-specific hidden folder (journal registry) |
| `drive.file`    | Read/write files created by the app (journal data)          |

These are narrow scopes — the app cannot access the user's other Drive files.
