# v0.17.3 — Medium priority fixes

Addresses 13 of 16 MEDIUM priority issues from the codebase audit (`.claude/notes/2026-03-20-6.md`).
Issues #17, #18, #19 (platform code deduplication) deferred to a dedicated refactor release — large blast radius with no user-facing benefit.
Issue #10 (web device key protection) was skipped in 17.2.

## Changes

### Phase 1: Quick Cleanups

- **Issue #24** (`app/page/[id].tsx`): Removed unused `t` from `handleDownloadImage` dependency array.
- **Issue #26** (`src/hooks/useFilter.ts`): Removed dead fallback branch in `matchesFilter` — `searchText` is always populated on `PagePreview`.
- **Issue #29** (`app/page/[id].tsx`): Removed duplicate `generateUUID` function, now imports from `@/lib/encryption/utils`.

### Phase 2: Minor Bug Fixes

- **Issue #25** (`src/components/journal/FilterBar.tsx`): Fixed bidirectional debounce sync — `localQuery` now syncs on all external `filter.query` changes, not just when cleared.
- **Issue #28** (`app/page/[id].tsx`): Added try-catch around `saveAttachment` in both `handleAddImage` and `handleAddFile` — failed saves now show an error alert instead of adding a broken attachment to the draft.
- **Issue #15** (`src/components/home/NewJournalModal.tsx`): Changed cloud import attachment downloads from `Promise.all` to `Promise.allSettled` — one failed attachment no longer aborts all others. Failures are collected and logged.
- **Issue #20** (`src/lib/backup/import.ts`, `import.web.ts`): Attachment `encrypted` flag now preserves the original value from the backup instead of being recalculated as `encrypted && !!derivedKey`. The data re-encryption is still gated on key availability, but the metadata flag reflects the true state.
- **Issue #21** (`src/lib/sync/gdrive/store.ts`): Added validation that access token is non-empty in `connect()`.

### Phase 3: Data Safety Hardening

- **Issue #16** (`src/lib/sync/gdrive/store.ts`): Folder cache key now always includes `parentId` (defaults to `'root'`), preventing collision for same-name folders in different parents.
- **Issue #22**: Extracted `safeJsonParse` to `src/lib/utils/json.ts`. Replaced all bare `JSON.parse(x) as T` calls in `local.ts`, `local.web.ts`, `import.ts`, `import.web.ts`, and `gdrive/store.ts`.
- **Issue #23** (`src/lib/backup/import.ts`, `import.web.ts`): Added `validateJournal()` call after parsing journal metadata from ZIP — corrupted or crafted backups now throw `ValidationError` instead of silently importing malformed data.
- **Issue #30** (`src/lib/storage/local.web.ts`): All IndexedDB transaction helpers (`idbGet`, `idbPut`, `idbDelete`, `idbDeletePrefix`, `idbListKeys`) now have 10-second timeout and `tx.onabort` handlers.

### Phase 4: DRY Cleanup

- **Issue #27** (`app/page/[id].tsx`): `handleOpenFile` now delegates to `downloadAttachment` utility instead of duplicating the web download logic. Removed unused `expo-sharing` import.

### Deferred

- **Issues #17, #18, #19** (platform code deduplication for storage, export, import) — deferred to dedicated refactor release.

## Tests

- 4 new tests in `src/lib/utils/__tests__/json.test.ts` for `safeJsonParse`
- Updated `src/lib/__tests__/gdrive-store.test.ts` error message assertions to match new shared `safeJsonParse` format
