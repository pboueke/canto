# 9.3 Image Loading UX & Journal Creation Redirect

## Changes

### Non-blocking image loading with queue (`src/hooks/useImageQueue.ts`)

- New `useImageQueue` hook: concurrency-limited (max 2) async queue for image loads in `ImageCarousel`
- Uses `InteractionManager.runAfterInteractions` to defer loading until navigation animations complete
- `setTimeout(0)` yield between each load so touches/navigation can be processed between decrypts
- Cancellation support: pending loads are dropped on unmount

### Shared thumbnail queue (`enqueueThumbnail`)

- Module-level serialized queue for all `PageListItem` thumbnails across the journal list
- One thumbnail loads at a time with `setTimeout(0)` yields between each
- Prevents 20+ concurrent decrypt operations when journal list renders

### ImageCarousel (`src/components/page/ImageCarousel.tsx`)

- Replaced fire-all-at-once `loadImageData` with `useImageQueue`
- Cancels pending loads on unmount

### PageListItem (`src/components/journal/PageListItem.tsx`)

- Replaced independent `InteractionManager` + `getAttachment` with shared `enqueueThumbnail` queue

### Journal "not found" redirect (`app/journal/[id].tsx`)

- When journal not found after loading, `router.replace('/')` redirects to homepage
- Shows spinner during brief redirect instead of static "Journal not found" text
- `useEffect` placed before early returns to respect React hooks rules

## Limitation

AES-GCM via `@noble/ciphers` is pure JS — each individual decrypt still blocks the thread for its duration. The yields ensure UI stays responsive _between_ loads but can't fix intra-operation blocking. Plan 9.4 addresses this with `react-native-quick-crypto` for native-thread crypto.
