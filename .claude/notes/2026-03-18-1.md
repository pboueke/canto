# 2026-03-18 - Google Auth Migration & Sync Encryption Fix

## Overview

Replaced `expo-auth-session` Google OAuth with `@react-native-google-signin/google-signin` (native Google Play Services) and fixed a critical bug where the sync engine couldn't read locally-encrypted journal data.

## Problem 1: OAuth Custom URI Scheme Blocked

`expo-auth-session` uses custom URI scheme redirects (`canto://`) which Google blocks for Android clients. Three approaches failed:

1. Removing `androidClientId` → library requires it on Android
2. Using only `webClientId` with generic `useAuthRequest` → Google doesn't accept custom schemes as redirect URIs on web clients either
3. Enabling custom URI scheme on Android client in Cloud Console → Google warns against it and doesn't expose redirect URI config

### Solution: Native Google Sign-In

Replaced `expo-auth-session` + `expo-web-browser` with `@react-native-google-signin/google-signin`:

- Uses Google Play Services natively — no redirect URIs needed
- `GoogleSignin.configure({ webClientId, scopes })` at module level
- `signIn()` → native account picker → tokens via `getTokens()`
- `signInSilently()` restores sessions on app restart
- Token refresh handled internally by Google Play Services

### Files Changed

- `src/contexts/GoogleAuthContext.tsx` — full rewrite
- `app.json` — swapped plugins (`expo-web-browser` → `@react-native-google-signin/google-signin`)
- `package.json` — added `@react-native-google-signin/google-signin`, removed `expo-auth-session`, `expo-web-browser`

### New Auth API

- `getAccessToken()` added to context — always returns a fresh token (Google Play Services handles refresh). Used by `SyncManagerContext` before each sync call.
- No more `expo-secure-store` for refresh tokens — library handles persistence internally.

## Problem 2: SHA-1 Fingerprint Mismatch

`DEVELOPER_ERROR` after sign-in. Debug keystore SHA-1 (`BB:78:...`) didn't match the actual build signing key (`5E:8F:...`). Expo prebuild generates its own keystore — `./gradlew signingReport` reveals the correct fingerprint.

## Problem 3: Sync JSON Parse Error

### Root Cause

Every Canto journal gets a `salt` at creation (even non-password-protected ones) and is encrypted with a derived key from empty password. The sync engine called `local.getJournal(journalId)` **without `derivedKey`**, so `readEncrypted` returned AES-GCM ciphertext (after device decrypt but missing password decrypt), which `JSON.parse` choked on.

### Fix

Threaded `derivedKey` through the entire sync chain:

- `SyncManager.syncJournal(journalId, accessToken, derivedKey)` — no longer ignores `_derivedKey`
- `SyncEngine.sync(journalId, derivedKey)` — passes to all `local.getJournal()`, `local.savePage()`, `local.deletePage()` calls
- `SyncManagerContext` already passed `derivedKey` from the UI — it was just being dropped at the manager level

### Files Changed

- `src/lib/sync/manager.ts` — `_derivedKey` → `derivedKey`, passed to engine
- `src/lib/sync/engine.ts` — `sync()` accepts and passes `derivedKey` to all local store calls
- `src/lib/__tests__/sync.test.ts` — updated expectations for extra `undefined` arg

## Other Improvements

- `SyncManager.connectIfNeeded()` → `connectWithToken()` — always updates the access token on each sync (prevents stale token issues)
- `GDriveRemoteStore.connect()` — no longer clears file ID cache on token refresh
- Added `safeJsonParse()` helper in `gdrive/store.ts` — all `JSON.parse` calls now surface the actual response content on failure
- Added diagnostic `JSON.parse` wrapper in `gdrive/api.ts` `handleResponse()` — surfaces response body on parse errors

## Status

Auth flow works on device (native Google sign-in sheet appears). Sync not yet validated end-to-end (requires SHA-1 fix in Cloud Console + rebuild).
