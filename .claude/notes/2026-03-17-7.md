# 2026-03-17 - Google Drive Sync Implementation (Requirement 11)

## Overview

Implemented per-journal Google Drive sync using the existing `RemoteStore` interface, Google OAuth via `expo-auth-session`, and the Google Drive REST API v3 via `fetch`.

## Architecture

### Authentication (`src/contexts/GoogleAuthContext.tsx`)

- Uses `expo-auth-session` in proxy-free mode with `canto://` scheme redirect
- Stores refresh token in `expo-secure-store` for session persistence
- Silent token refresh on app start
- Provides `signIn()`, `signOut()`, `accessToken`, `user`, `isSignedIn`

### Google Drive API (`src/lib/sync/gdrive/api.ts`)

- Thin wrapper around Drive REST API v3 using `fetch`
- Functions: `listFiles`, `getFile`, `getFileContent`, `createFile`, `updateFile`, `deleteFile`
- All use multipart upload for create/update operations

### GDriveRemoteStore (`src/lib/sync/gdrive/store.ts`)

- Implements `RemoteStore` interface
- **Drive file structure:**
  - `appDataFolder/canto-journals.json` — registry (hidden from user)
  - `Canto/<journalId>/meta.json` — journal metadata
  - `Canto/<journalId>/pages/<pageId>.json` — individual pages
  - `Canto/<journalId>/attachments/<name>` — attachment binaries
- In-memory file ID cache to minimize API calls
- Attachment paths use `gdrive://<journalId>/attachments/<name>` format

### Sync Manager (`src/lib/sync/manager.ts`)

- Wraps `SyncEngine` + `GDriveRemoteStore`
- Per-journal sync state: `idle | syncing | error`
- Concurrent sync prevention via locks
- Debounced auto-sync (5s default)
- Persists last sync timestamp in AsyncStorage

### Context (`src/contexts/SyncManagerContext.tsx`)

- Provides `syncJournal()`, `scheduleSyncDebounced()`, `getSyncState()` to components
- Depends on `GoogleAuthContext` for access token

## UI Components

### AccountButton (`src/components/home/AccountButton.tsx`)

- Shows "Connect account" with cloud icon when not signed in
- Shows circular avatar (photo or initials) when signed in
- Popover modal with email and sign out option

### SyncModal (`src/components/journal/SyncModal.tsx`)

- Modal triggered from journal header cloud icon
- States: not signed in → sign in button; signed in but not syncing → enable button; syncing → sync now + auto-sync toggle + disable
- Shows last synced time and sync feedback

## Status: Untested on Device

The Google Drive sync feature has **not been tested on a real device yet**. All code was written and unit-tested only. The OAuth flow requires a native dev build (`npx expo run:android`) — it does not work in Expo Go because `expo-auth-session` needs the native `com.canto.app:/oauthredirect` deep-link scheme, which Expo Go cannot handle. Initial attempt to test on-device was blocked by the need to set up USB debugging and build a dev client. The full integration (auth flow → Drive API calls → sync round-trip) remains to be validated.
