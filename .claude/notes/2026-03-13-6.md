# v0.8.3 — Device key rotation bugfix

## Bug: passwords stop working after rotating the device key

Three related bugs in the device key rotation flow caused data loss:

### Bug 1: `reencryptAll` called `readIndex()` after re-encrypting the index (local.ts)

After re-encrypting the index file with `newDeviceEncrypt`, the code called `readIndex()` which
used the encryption singleton — still caching the OLD key. Decryption failed silently (returned
`null` → empty journals list), so **no journal/page/attachment data was ever re-encrypted**. Only
the index got rotated, leaving the system in an inconsistent state.

**Fix**: parse the decrypted index content directly from `oldDeviceDecrypt` output instead of
calling `readIndex()`.

### Bug 2: cached device key never cleared after rotation (SecuritySettingsModal.tsx)

After `reencryptAll` completed, the encryption singleton's `cachedKey` still held the old key.
All subsequent read/write operations used the stale key.

**Fix**: call `getEncryptionService().clearSession()` after successful re-encryption.

### Bug 3: `oldDecrypt` used SecureStore key instead of cached key (SecuritySettingsModal.tsx)

`handleRotateKey` created `oldDecrypt` using the key from `rotateKey()` (read from SecureStore).
But the actual data on disk was encrypted with the singleton's **cached** key, which could differ
from SecureStore if a previous rotation partially failed (Bug 1 re-encrypted the index but not
journal data, so the index was on the new SecureStore key while data remained on the cached key).

**Fix**: `oldDecrypt` now tries both keys — first the singleton's cached key (for journal data
still on the original key), falling back to the SecureStore key (for the index that was already
re-encrypted by a previous failed rotation).

## Files modified

- `src/lib/storage/local.ts` — `reencryptAll` parses decrypted index directly instead of calling `readIndex()`
- `src/components/home/SecuritySettingsModal.tsx` — dual-key fallback `oldDecrypt`, `clearSession()` after rotation
- `src/lib/__tests__/localStorage.test.ts` — added `MockFile.name`, `parentDirectory`, `move()`; 4 new tests covering key rotation scenarios (readable with new key, unreadable with old key, multiple journals, inconsistent state from previous failed rotation)
