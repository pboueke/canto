# v0.16.0 — canto-data: versioned data model library

## What was done

Extracted the Canto data model into `canto-data`, an MIT-licensed workspace package at `packages/canto-data/`. The app (GPLv3) imports from it via npm workspaces, enabling third-party tools to interoperate with Canto journals without copyleft obligations.

## Key decisions

- **MIT license for data portability**: The app stays GPLv3, but the data layer is MIT so anyone can build tools that read/write Canto journals.
- **Monorepo workspace** (not separate repo): `packages/canto-data/` with its own `package.json`, `tsconfig.json`, and `LICENSE`. Publishable to npm when ready.
- **Schema versioning is separate from package versioning**: `SCHEMA_VERSION = "1.0.0"` is the data format version (bumped when schema changes). Package version tracks the app version (`0.16.0`).
- **`schemaVersion` is optional on JournalContent**: Legacy journals without it are treated as `"1.0.0"`. Forward-only migrations.
- **`SyncProvider` type moved to data module**: Broke the circular dependency where `models/types.ts` imported from `lib/sync/types.ts`. Now `sync/types.ts` re-exports from `canto-data`.
- **No external dependencies**: Validation is hand-written type guards (no zod/ajv). Format utilities are pure functions (no JSZip, no expo).
