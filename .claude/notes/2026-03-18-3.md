# v0.11.3 — Provider-Agnostic Sync Architecture

**Date:** 2026-03-18

## Summary

Refactored the sync layer to eliminate hardcoded Google Drive dependencies from the generic sync interface. The `SyncEngine` and `SyncManager` are now fully provider-agnostic. Provider selection happens at the context layer (`SyncManagerContext`), making it straightforward to add new sync providers in the future.

## Key Changes

### Interface Changes (`src/lib/sync/types.ts`)

- Added `SyncProvider` type union (`'gdrive'`)
- Added `provider`, `isRemotePath()`, `buildRemotePath()` to `RemoteStore` interface
- `SyncEngine` uses these methods instead of hardcoded `gdrive://` string checks

### Architecture Change

- **Before:** `SyncManager` created `GDriveRemoteStore` internally in its constructor
- **After:** `SyncManager` accepts any `RemoteStore` via constructor. `SyncManagerContext` is the composition root that creates `GDriveRemoteStore` and passes it in.

### UI Changes

- `AccountButton` removed from `InfoBox` (settings area) and added to home page footer (`app/index.tsx`)
- When signed in: shows avatar + "Logged in with Google"
- New `SyncProviderModal` appears before auth — shows available providers (Google Drive)
- `SyncManagerContext` now exposes `provider: SyncProvider | null`

### Model Change

- `JournalSettings.syncProvider` uses imported `SyncProvider` type instead of inline `'gdrive'` literal
