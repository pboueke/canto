# Code Review Fixes: Sync, Encryption & Storage (Plan 13)

## Summary

Addressed findings from a code review of `src/lib/{sync,encryption,storage}` modules.
All 439 tests pass (33 new), lint clean.

## Changes Made

### Phase 1 — Critical

1. **`engine.ts` — parallel() race condition**: Replaced shared index counter with `queue.shift()` approach. Array.shift() is atomic within a single JS microtask, so no two workers can grab the same item.

2. **`engine.ts` — syncAll() derivedKey**: Added `getKey` callback parameter so encrypted journals receive their derived keys during bulk sync.

3. **`gdrive/store.ts` — connect() cache clearing**: Was inverted (cleared when token unchanged + cache empty = no-op). Now clears cache on first connection only (`accessToken === null` → first connect).

4. **`password.ts` — KDF iterations**: Made `createPasswordEncryption()` accept an `iterations` parameter (defaults to `LEGACY_KDF_ITERATIONS`). Note: the main journal flow already used correct per-journal iterations via `JournalKeyContext`; this fixes the provider for consistency. Also standardized key zeroing to use try/finally in both encrypt and decrypt.

### Phase 2 — High

5. **`gdrive/store.ts` — query injection**: Added `escapeQuery()` helper (escapes `\` and `'`), applied to all 6 ODATA query interpolation sites.

6. **`engine.ts` — silent attachment failure**: Now logs a warning when local attachment data is missing instead of silently skipping.

7. **`storage/local.ts` — deleteJournal order**: Reversed to delete directory first, then update index. If dir delete fails, journal stays visible (recoverable). Previously orphaned data.

8. **`storage/local.ts` — attachment re-encryption**: `reencryptJournal()` now iterates the attachments directory and re-encrypts each file with the new key. Progress callback updated to include attachment count.

9. **`encryption/ratelimit.ts` — race condition**: Added promise-based mutex (`serialize()`) around `attempt()` to prevent concurrent calls from reading stale state.

10. **`manager.ts` — lost promise**: Added `.catch()` to debounced `syncJournal()` call. Errors are already captured in state via the try/catch inside `syncJournal`, so the catch is just to prevent unhandled rejection.

11. **`gdrive/store.ts` — duplicate folder creation**: Added `folderInflight` Map for promise dedup. Concurrent `getOrCreateFolder()` calls for the same key await the same promise.

12. **`gdrive/api.ts` — error message sanitization**: Removed response body from thrown errors. Error messages now only contain status code (`Drive API error (404)`).

### Phase 3 — Medium

13. **`gdrive/store.ts` — Promise.allSettled**: Page downloads now use `Promise.allSettled()` so one corrupted page doesn't fail the entire journal download.

14. **`gdrive/store.ts` — deleteJournal cache purge**: Changed from `key.includes(journalId)` to matching by folder ID to prevent accidental cross-journal cache invalidation.

15. **`encryption/utils.ts` — base64 validation**: Added check for invalid characters (lookup === 255) during decoding. Padding characters (`=`) handled correctly.

16. **`encryption/utils.ts` — thread yield consistency**: Added `await yieldThread()` to `aesGcmEncryptBytes()` and `aesGcmDecryptBytes()` to match string variants.

17. **`encryption/utils.ts` — key size validation**: All four AES functions now assert `key.length === 32` before importing.

18. **`gdrive/api.ts` — retry on transient errors**: Added `fetchWithRetry()` that retries once on 5xx or network errors with 1s backoff. All fetch calls now use it.

### Test Updates

- `gdrive-api.test.ts`: Updated error message assertions to match sanitized format. Added 5xx mock duplication for retry. Changed "error diagnostics" tests to verify content is NOT leaked.
- `gdrive-store.test.ts`: Updated safeJsonParse test to verify content is not in error message.
