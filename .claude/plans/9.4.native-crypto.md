# Plan: 9.4 Native Crypto Backend (react-native-quick-crypto)

## Problem

AES-GCM decryption via `@noble/ciphers` is pure JavaScript — each call blocks the JS thread synchronously. For image attachments (2MB+), this freezes the UI for hundreds of milliseconds per image, even with the queue/yield mitigations from 9.3.

## Goal

Replace the synchronous `@noble/ciphers` AES-GCM calls with `react-native-quick-crypto`, which runs crypto operations on a native thread via JSI, making them genuinely non-blocking.

## Analysis

### Current crypto usage of `@noble/ciphers`

1. **`src/lib/encryption/utils.ts`** — `aesGcmEncrypt`, `aesGcmDecrypt`, `aesGcmEncryptBytes`, `aesGcmDecryptBytes`
   - Uses `gcm` from `@noble/ciphers/aes.js`
   - Called by device encryption (`device.ts`) and directly in storage layer (`local.ts`) for password-layer encryption
2. **`src/lib/encryption/device.ts`** — imports `bytesToHex`, `hexToBytes` from `@noble/ciphers/utils.js`

### Other crypto dependencies (not affected)

- `@noble/hashes` — used for PBKDF2 in `JournalKeyContext.tsx`. Keep as-is (PBKDF2 only runs once at unlock, not per-image).
- `crypto.getRandomValues()` — Hermes native, no change needed.

## Implementation

### Step 1: Install `react-native-quick-crypto`

User runs: `npm install react-native-quick-crypto --legacy-peer-deps`

The library provides a Node.js-compatible `crypto` API backed by OpenSSL via JSI. It exposes `createCipheriv` / `createDecipheriv` for AES-GCM.

### Step 2: Replace AES-GCM in `src/lib/encryption/utils.ts`

Replace `@noble/ciphers` AES-GCM with `react-native-quick-crypto`:

**Key change**: The function signatures become `async` since quick-crypto operations can yield to the native thread. All callers already `await` these functions.

### Step 3: Update `src/lib/encryption/device.ts`

Replace `bytesToHex` / `hexToBytes` imports from `@noble/ciphers/utils.js` with a local implementation or `react-native-quick-crypto`'s Buffer.

### Step 4: Update `src/lib/storage/local.ts`

The direct `aesGcmEncrypt` / `aesGcmDecrypt` calls in `saveAttachment` and `getAttachment` need to be `await`ed (currently synchronous calls).

### Step 5: Update `src/lib/backup/export.ts` and `import.ts`

These files also use `aesGcmEncryptBytes` / `aesGcmDecryptBytes` — update to async.

### Step 6: Remove `@noble/ciphers` dependency

After migration, `@noble/ciphers` is no longer needed. Remove from `package.json`.

### Step 7: Verify

- Run `npx tsc --noEmit` to check types
- Run existing tests
- User tests: create journal, add encrypted images, verify decrypt, export/import backup

## Considerations

- `react-native-quick-crypto` requires a native rebuild (not compatible with Expo Go — needs dev client or bare workflow). Verify this works with the current Expo setup.
- The `aesGcmEncryptBytes` / `aesGcmDecryptBytes` variants (used for backup ZIP) need equivalent async replacements.
- The base64 encode/decode helpers (`uint8ToBase64`, `base64ToUint8`) can stay as-is — they're fast enough and don't involve crypto.
- After this change, the `setTimeout(0)` yields in `useImageQueue` are still beneficial for managing queue pacing, but the UI will no longer freeze during individual image decrypts.
