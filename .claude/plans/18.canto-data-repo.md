# Plan 18: Split canto-data into separate repository

## Overview

Move `packages/canto-data/` from the canto monorepo into the existing `~/Repositories/canto-data` repository. Each repo gets independent versioning. The canto app consumes canto-data as an npm dependency. The canto-data repo is structured for npm publishing with GitHub Actions CI/CD.

## Current State

- **Canto app**: `v0.17.8`, GPLv3, monorepo with `packages/canto-data/`
- **canto-data package**: `v0.17.8` (in `packages/canto-data/`), MIT licensed, zero dependencies
- **`~/Repositories/canto-data`**: exists with just LICENSE (MIT) + README stub
- **App imports**: 51 files import from `@/data`, which re-exports from `canto-data`
- **`src/data/`**: thin re-export layer (4 files) — will be removed
- **`SCHEMA_VERSION`**: `0.17.0` (already decoupled from package version)
- **`DATA.md`**: comprehensive data model docs, lives in canto root

## Target State

- **canto-data repo** (`~/Repositories/canto-data`): v1.0.0, MIT, npm-publishable, GitHub Actions CI
- **canto repo**: stays at v0.17.8, GPLv3, depends on `canto-data` from npm
- **App code**: imports directly from `canto-data` (no `@/data` re-export layer)
- **DATA.md**: moved to canto-data repo, canto README links to it

## Phase 2: GitHub Actions CI/CD for canto-data

### 2.1 Create `.github/workflows/ci.yml`

Runs on every push and PR to `main`:

- Lint (if added) + typecheck
- Run tests with coverage
- Build (`tsc`)

```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [18, 20, 22]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
      - run: npm ci
      - run: npm run test:ci
      - run: npm run build
```

CI uses `test:ci` which runs with `--coverage` — jest's `coverageThreshold` enforces 100% across branches, functions, lines, and statements. The build will fail if coverage drops below 100%.

### 2.2 Create `.github/workflows/publish.yml`

Auto-publishes to npm when a push to `main` includes a version bump:

```yaml
name: Publish to npm
on:
  push:
    branches: [main]
jobs:
  publish:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 2
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          registry-url: https://registry.npmjs.org
      - run: npm ci
      - run: npm test
      - run: npm run build
      - name: Check if version changed
        id: version
        run: |
          CURRENT=$(node -p "require('./package.json').version")
          PREVIOUS=$(git show HEAD~1:package.json 2>/dev/null | node -p "JSON.parse(require('fs').readFileSync('/dev/stdin','utf8')).version" 2>/dev/null || echo "0.0.0")
          if [ "$CURRENT" != "$PREVIOUS" ]; then
            echo "changed=true" >> $GITHUB_OUTPUT
            echo "version=$CURRENT" >> $GITHUB_OUTPUT
          fi
      - name: Publish
        if: steps.version.outputs.changed == 'true'
        run: npm publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
      - name: Create git tag
        if: steps.version.outputs.changed == 'true'
        run: |
          git tag "v${{ steps.version.outputs.version }}"
          git push origin "v${{ steps.version.outputs.version }}"
```

### 2.3 Document npm setup instructions

Add to README or a PUBLISHING.md:

1. **npm account**: Create/login at npmjs.com
2. **npm token**: Generate an automation token at npmjs.com → Access Tokens → Generate New Token (Automation)
3. **GitHub secret**: Add the token as `NPM_TOKEN` in GitHub repo → Settings → Secrets → Actions
4. **First publish**: Can be done manually with `npm publish` after `npm login`, or by pushing v1.0.0 to main
5. **Subsequent publishes**: Bump version in package.json, merge to main → auto-published

## npm Publishing Setup (full instructions)

### One-time setup

1. **Create npm account** (if not exists): https://www.npmjs.com/signup
2. **Login locally**: `npm login`
3. **Generate automation token**: npmjs.com → Avatar → Access Tokens → Generate New Token → select "Automation" type
4. **Add to GitHub**: Go to `github.com/pboueke/canto-data` → Settings → Secrets and variables → Actions → New repository secret → Name: `NPM_TOKEN`, Value: paste token

### Publishing workflow

- **Automatic**: Bump version in `package.json`, merge PR to `main` → GitHub Actions publishes to npm and creates a git tag
- **Manual** (first time or emergency): `npm run build && npm publish`

### Version bump process

```bash
# In canto-data repo:
npm version patch   # 1.0.0 → 1.0.1 (bug fix)
npm version minor   # 1.0.0 → 1.1.0 (new feature)
npm version major   # 1.0.0 → 2.0.0 (breaking change)
git push && git push --tags
# Or just edit package.json and push — CI will detect the version change
```

### After publishing a new version

```bash
# In canto repo:
npm install canto-data@latest
# Commit the updated package.json + package-lock.json
```
