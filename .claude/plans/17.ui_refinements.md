# Plan: Requirement 17 — UI Refinements

## Context

Canto is at v0.16.0, post-Play Store launch prep. This requirement addresses a collection of UI polish items: image carousel enhancements, thumbnail sizing, an encrypted image rendering bug, search improvements, dead code removal, accessibility, a help button, and a cloud import UUID fix. These are independent, isolated refinements — no new architecture or services needed.

**Root cause**: `ImageCarousel.tsx:53` — the `useEffect` dependency array uses `activeImages.length` instead of a stable key. On edit→save transitions, `cancelAll()` fires as cleanup but loaded state can become stale.

**Files:**

- `src/components/page/ImageCarousel.tsx` — Fix useEffect dependency to use a stable images key (e.g., `activeImages.map(i => i.id).join(',')`) instead of just `.length`. Ensure `cancelAll()` in cleanup does NOT reset `loadedImages` state — only cancels pending queue entries (already correct in `useImageQueue.ts`, the issue is the re-render cycle).
- `src/hooks/useImageQueue.ts` — Verify that `loadedRef` correctly persists across re-renders (it does via useRef). The fix is primarily in the carousel's effect dependency.

**Tests:**

- New test in `src/components/page/__tests__/ImageCarousel.test.tsx`: simulate edit→save→edit→save cycle, verify images remain rendered.
- Test that `cancelAll` only cancels pending loads, not already-loaded images.

### Phase 5: Remove Dead Markdown Tips Setting + Schema Migration

The canto-data package already has a complete migration framework (`migration.ts`, `version.ts`, `migrations/index.ts`) with zero migrations registered. This is the first real use of it.

**Schema version bump:** `1.0.0` → `1.1.0` (minor — backwards compatible removal of an optional field).

**Migration files:**

- `packages/canto-data/src/version.ts` — Bump `SCHEMA_VERSION` from `'1.0.0'` to `'1.1.0'`.
- Create `packages/canto-data/src/migrations/v1_0_0_to_v1_1_0.ts` — Migration that strips `showMarkdownPlaceholder` from `settings` object if present. This is a no-op migration (the field is simply ignored), but it documents the schema change and validates the migration framework.
  ```
  migrate(data: unknown): unknown {
    // Strip showMarkdownPlaceholder from settings if present
    if (data && typeof data === 'object' && 'settings' in data) {
      const settings = (data as any).settings;
      if (settings && 'showMarkdownPlaceholder' in settings) {
        delete settings.showMarkdownPlaceholder;
      }
    }
    return data;
  }
  ```
- `packages/canto-data/src/migrations/index.ts` — Register the migration in `MIGRATIONS` array.

**Type/validation removal:**

- `packages/canto-data/src/types.ts` — Remove `showMarkdownPlaceholder` from `JournalSettings` interface and `DEFAULT_JOURNAL_SETTINGS`.

```

```
