# Plan 20 — Editor Styling and Android DEX Optimization

> **Agent provenance:** This plan was authored and implemented by OpenAI `gpt-5.6-sol` in the Pi coding-agent harness, with read-only reviewer/scout subagents used for independent checks. The repository user initiated the work with: “review requirement file 20 at .claude and create a new implementation plan,” then explicitly authorized implementation and subsequent corrections. ## Requirement review

Requirement source: `.claude/requirements/20.styling_and_dex`

The requirement has two independent outcomes:

1. The main page text editor must look intentional and must not let a new-line caret collide with its border.
2. The Android release build used by the local build script must enable enough DEX optimization to meet Google Play's minimum threshold.

Repository inspection found the following relevant facts:

- `PageContent` currently gives the native multiline `TextInput` `flex: 1` inside a parent with no intrinsic edit-mode minimum height. That sizing relationship can collapse around a new line. Web has a separate grow-only `scrollHeight` path and a fixed `400`-pixel container minimum.
- The page already uses `KeyboardAwareScrollView`; the editor should remain part of that outer scroll surface instead of introducing nested scrolling.
- Android release minification and resource shrinking are both disabled by default because the generated Gradle properties are absent.
- The generated app build uses `proguard-android.txt`, not the optimizing `proguard-android-optimize.txt` baseline.
- Most of `android/` is intentionally ignored, so direct edits to generated Gradle files are not a durable source of truth.
- The project resolves Android Gradle Plugin 8.12.0. This supports R8 metadata and optimized resource shrinking.
- The tracked `CantoArchive` Kotlin bridge and its manual `MainApplication` registration are not safe under `expo prebuild --clean`; a clean/fresh prebuild removes them unless a config plugin regenerates them.
- The current ignored `.build_android.sh` builds `bundleRelease`, but embeds signing secrets and does not run prebuild.
- `app.json` reports Android `versionCode: 22`, while the current generated Android project reports `26`. A clean local release build therefore needs a corrected tracked version code.

Google's current DEX guidance treats optimization, obfuscation, and shrinking as separate Android vitals metrics with a 25% minimum threshold for qualifying apps. Play is authoritative; local analyzer values can differ from Play's values. References:

- <https://developer.android.com/topic/performance/vitals/code-optimization>
- <https://developer.android.com/topic/performance/app-optimization/enable-app-optimization>

## Decisions resolved with the user

### Editor

- Scope is the main editor card only, not a full page redesign.
- The editor grows and shrinks with its content; the page's outer `KeyboardAwareScrollView` remains the only scrolling surface.
- Empty edit mode provides a writing canvas of approximately 16 text lines. The minimum scales with the selected font size.
- Edit mode uses the large minimum. A later user-requested refinement gives read mode a smaller, scale-derived four-line minimum.
- Entering edit mode does not automatically focus the input or open the keyboard.
- A later user-requested correction removes the inner `TextInput` border, outline, underline, and box shadow in all focus states because the platform/web focus border overlapped the caret and line-start text. The enclosing section remains the sole themed border.
- Acceptance platforms are Android and web. iOS manual QA is deferred, though shared code must remain type-safe and should not deliberately regress iOS.

### Android optimization

- The acceptance gate covers all three reported DEX metrics: optimization, obfuscation, and shrinking must each be at least 25% when Play reports them.
- Tracked Expo configuration is the source of truth; ignored generated Gradle files are not.
- Use the SDK-compatible `expo-build-properties` plugin for release minification and resource shrinking.
- Use R8's optimizing default configuration and AGP 8.12 optimized resource shrinking.
- Preserve existing project and library keep rules initially.
- Do not make speculative keep-rule changes. If Play remains below 25% and evidence identifies a keep rule as the blocker, one narrowly scoped exception may be proposed and tested. Stop for user review if safe narrowing cannot be demonstrated.
- Verification combines local release artifacts with a Play internal-track check.
- Do not add a full Android build job to normal CI. Config-plugin unit tests may run through the existing Jest job, but clean prebuild, release AAB generation, artifact inspection, and Play verification remain release-time gates.

### Release build and versioning

- Add a tracked, sanitized Android release-build script as the canonical build path.
- Move signing values into ignored `android_build.env`; commit `android_build.env.example` with placeholders.
- Sanitize the existing ignored `.build_android.sh` into a no-secret local wrapper around the tracked script.
- Make `CantoArchive` prebuild-safe before making clean prebuild part of the release script.
- Target app version `0.20.0` and Android `versionCode: 27`.
- Optimized-release smoke testing is limited to launch, journal open, multiline edit/save, and native backup import.

## Out of scope

- Full restyling of tags, media, files, comments, page header, or floating action buttons.
- An internally scrolling or viewport-capped text editor.
- Automatic keyboard focus when edit mode opens.
- iOS manual acceptance testing in this requirement.
- A new Android release-build CI job.
- Speculative removal of React Native, TurboModule, or library keep rules.
- Changing EAS production behavior beyond what naturally consumes the shared Expo config; the local tracked build script is the canonical release path for this requirement.
- Rotation or replacement of the upload keystore itself.

## Workstream A — Make Android prebuild deterministic

This workstream must land before the release script starts using clean prebuild.

### A1. Extract local config plugins

Refactor the inline release-signing mutation out of `app.config.js` into testable local plugin modules under `plugins/`:

- `plugins/withReleaseSigningConfig.js`
  - Preserve the current release keystore filename, alias, and environment-variable password behavior.
  - Make every mutation idempotent.
  - Fail with a clear error if the expected Expo-generated Gradle anchor changes instead of silently producing a debug-signed release.
- `plugins/withAndroidReleaseOptimization.js`
  - Ensure the generated release build uses `proguard-android-optimize.txt` rather than `proguard-android.txt`.
  - Add/update `android.r8.optimizedResourceShrinking=true` in generated `gradle.properties` for AGP 8.12.
  - Keep project keep rules in `android/app/proguard-rules.pro`.
  - Make transformations idempotent and assert the expected release block exists.
- `plugins/withCantoArchive.js`
  - Copy the canonical Kotlin module/package sources into the generated Android package directory.
  - Register `CantoArchivePackage()` in the generated Kotlin `MainApplication` exactly once.
  - Validate the expected package/application structure and fail loudly on an unsupported Expo template.

Prefer small exported transformation helpers so fixture tests do not need to run a full Android build.

### A2. Move native archive source out of the generated tree

Create a tracked canonical source location outside `android/`, for example:

- `native/canto-archive/CantoArchiveModule.kt`
- `native/canto-archive/CantoArchivePackage.kt`

Move the current implementations without changing their runtime contract. The config plugin copies these files into the generated package path during prebuild.

After the plugin is proven, remove the generated-tree copies from Git so there is only one canonical source. Do not change the TypeScript `NativeModules.CantoArchive` interface or archive behavior in this requirement.

### A3. Compose plugins in Expo config

Modify `app.config.js` to:

- load `app.json` as today;
- append/configure `expo-build-properties` with:
  - `android.enableMinifyInReleaseBuilds: true`;
  - `android.enableShrinkResourcesInReleaseBuilds: true`;
- apply the signing, optimization, and archive plugins in a deterministic order;
- preserve all existing Expo plugins from `app.json`;
- avoid duplicate plugin entries across repeated config evaluation.

Install the Expo-SDK-compatible package with `npx expo install expo-build-properties` so `package.json` and `package-lock.json` remain aligned with SDK 55.

### A4. Config-plugin regression tests

Add fixture-based Jest tests under `plugins/__tests__/` (or `scripts/__tests__/` if the Jest environment resolves that location more cleanly):

- signing is inserted once and release points to `signingConfigs.release`;
- minify and shrink settings are represented by Expo config;
- the default ProGuard file is changed to the optimizing variant exactly once;
- the optimized resource-shrinking Gradle property is inserted or updated idempotently;
- archive Kotlin files are copied to the configured package path;
- `CantoArchivePackage()` is registered exactly once;
- unsupported/missing anchors produce actionable errors rather than silent partial configuration.

A clean-prebuild smoke test remains a manual release gate, not a normal CI Android build.

## Workstream B — Reproducible sanitized Android release script

### B1. Secret files

Update `.gitignore` to ignore `android_build.env` explicitly.

Add `android_build.env.example` containing names and documentation only, with no secret values. Expected inputs:

- `KEYSTORE_PASSWORD` — required;
- `KEY_PASSWORD` — required;
- `ANDROID_KEYSTORE_PATH` — optional, defaulting to the ignored repository-root `upload-keystore.jks`;
- optionally `ANDROID_BUILD_ENV_FILE` as a shell-level override for selecting a different env file rather than a value stored inside the file.

The env file is developer-local and must never be copied into build artifacts.

### B2. Tracked build script

Add `scripts/build-android-release.sh` with `set -euo pipefail`. It must:

1. Resolve paths relative to the repository root, not the caller's current directory.
2. Source `android_build.env` (or `ANDROID_BUILD_ENV_FILE`) and validate required variables without printing their values.
3. Validate the keystore exists.
4. Run `npx expo prebuild --clean --platform android --no-install`.
5. Copy the selected keystore to the generated path expected by the signing plugin.
6. Assert before building that:
   - generated `MainApplication.kt` registers `CantoArchivePackage()`;
   - both archive Kotlin files exist;
   - release minification is enabled;
   - resource shrinking is enabled;
   - `proguard-android-optimize.txt` is selected;
   - `android.r8.optimizedResourceShrinking=true` is present;
   - generated version name/code are `0.20.0` / `27`.
7. Run `android/gradlew bundleRelease` without echoing secrets.
8. Print the AAB and R8 artifact paths on success.

Do not silently patch generated files in this script. A failed assertion means the Expo config/plugin source of truth is wrong and the build must stop.

### B3. Local wrapper migration

Rewrite the ignored `.build_android.sh` locally as a minimal wrapper that delegates to `scripts/build-android-release.sh`. Remove embedded passwords from that file. Because the wrapper is ignored, record this local-only migration in the implementation note; the tracked script and example env file are the durable repository changes.

### B4. Contributor documentation

Update `CONTRIBUTING.md` Android setup with:

- copying `android_build.env.example` to `android_build.env`;
- setting the keystore path and passwords locally;
- invoking the tracked release script;
- release artifact locations;
- warning that Play verification is still required;
- a statement that credentials and the keystore must remain untracked.

## Workstream C — Editor card layout and styling

### C1. Replace fragile native flex sizing

Modify `src/components/page/PageContent.tsx`:

- remove `flex: 1` as the native multiline input's sizing mechanism;
- derive the edit-mode minimum from the active line height and `EDITOR_MIN_LINES = 16` rather than a platform-only magic container height;
- keep the card's outer padding as the border-to-caret clearance boundary;
- normalize the `TextInput`'s own platform padding so Android does not add uneven hidden insets;
- set `scrollEnabled={false}` while editing so the input grows within the page instead of becoming a nested scroll area;
- keep `textAlignVertical="top"`;
- track native content height through `onContentSizeChange` and clamp to the scaled minimum;
- permit height to decrease after deletion, never below the minimum.

The content-height state should be reset/reconciled when switching edit mode, changing font scale, or loading a different content value so stale height from a previous page cannot leak into the next one.

### C2. Preserve and improve web auto-sizing

Replace the current grow-only web measurement with grow-and-shrink behavior:

- measure the underlying textarea's natural `scrollHeight` after content/font changes;
- temporarily release its explicit height before measuring shrinkage;
- apply the same scaled 16-line minimum used on native;
- preserve the outer page scroll position/caret during remeasurement so the recent web scroll-jump fix does not regress;
- keep the textarea's internal overflow hidden and internal scrolling disabled.

Avoid browser globals on native execution paths. If measurement logic becomes difficult to test in `PageContent`, extract a small pure height-clamping helper rather than adding another large component abstraction.

### C3. Inner input border suppression

Keep the enclosing section as the only themed border and explicitly suppress platform-specific inner input decoration:

- disable the Android text-input underline;
- set the inner `TextInput` border and outline widths to zero;
- remove inner box shadow;
- keep the input background transparent so the enclosing themed surface remains visible;
- do not add focus-state border styling or new theme tokens.

Do not autofocus when edit mode starts.

### C4. Editor regression tests

Extend `src/components/page/__tests__/PageContent.test.tsx` and the existing scale test as appropriate:

- edit mode renders a non-scrolling multiline input with top alignment;
- edit mode has a scaled 16-line minimum and read mode has a scaled four-line minimum;
- native content-size growth increases height;
- a later smaller content-size event shrinks height back toward, but not below, the minimum;
- the inner input remains borderless, outline-free, underline-free, and shadow-free across focus changes;
- font scale changes line height and the derived minimum coherently;
- existing Markdown rendering and web-specific sizing behavior remain covered.

Where React Native's test renderer cannot model DOM `scrollHeight`, unit-test the extracted clamp/measurement decisions and retain the real browser behavior in manual QA.

### Web editor QA

In at least one Chromium browser:

1. Open a short page and enter edit mode; the editor starts at approximately 16 lines without auto-focusing.
2. Tap the editor; no inner focus border, outline, underline, or shadow appears over the caret or line-start text.

4. Delete enough text to go below the previous height; the card shrinks to the minimum.
5. Confirm growth/shrink does not jump the outer page unexpectedly.
6. Leave edit mode; short Markdown content retains the scale-derived four-line viewing minimum.
7. Repeat with default and x-large font settings and at least one light and one dark theme.

### Android editor QA

On an Android device/emulator:

1. Repeat the web editor checks for edit/view minimum sizes, border suppression, growth, and shrink.
2. Type a new line at the bottom edge and confirm the caret remains visible and does not overlap the card border.
3. Type beyond the visible viewport with the keyboard open and confirm the outer page scroll keeps the caret visible.
4. Confirm scrolling gestures move the page, not a nested text field.
5. Repeat with default and x-large font settings and at least one light and one dark theme.

## Risk register and rollback

### R8 causes a release-only failure

- Retrace with the release `mapping.txt`.
- Identify the exact class/native boundary involved.
- Add the narrowest justified keep rule; do not disable minification globally.
- Rebuild and rerun the critical-path smoke test.

### Play remains below 25%

- Compare Play's metric with `r8.json`, mapping/configuration outputs, and APK Analyzer.
- Identify whether an existing project/library keep rule protects a disproportionate package.
- Do not edit keep rules speculatively.
- Present one evidence-backed narrowing proposal and its release smoke-test impact.
- If safe narrowing cannot be shown, stop with the measured scores, identified blocker, attempted diagnostics, and next decision needed.

### Clean prebuild loses the native archive bridge

- The release script must fail before Gradle if source files or registration are absent.
- Do not work around the failure by skipping prebuild or hand-editing generated Android files.
- Fix the archive config plugin/fixture first and rerun from clean prebuild.

### Editor regresses web scrolling

- Revert only the shrink measurement strategy, not the corrected native sizing or inner-input border suppression.
- Preserve the 16-line minimum and caret inset while replacing the web measurement with a scroll-position-safe implementation.

### Secret leakage

- The build script must never use shell tracing or print loaded values.
- Before commit/release, check Git status and staged diffs for `android_build.env`, keystores, generated Android credentials, and build outputs.
- If a real credential is committed or logged, stop and rotate it before continuing.
