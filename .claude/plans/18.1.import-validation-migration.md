# Plan 18.1: Add settings validation to import pipeline

## Overview

The import pipeline (`import.ts` / `import.web.ts`) validates journal base fields via `validateJournal()` but doesn't validate settings. Malformed or tampered settings aren't caught at the boundary.

Since the app has not been published, there are no legacy backups in the wild. Migration logic (`migrateIfNeeded`) is not needed in the import path — when a real schema change ships post-publication, migration can be added to both storage and import at that point.

## Current flow (both native and web)

1. Parse manifest via `parseManifest()`
2. Read `journal.json` → `safeJsonParse()` → `validateJournal()` (base fields only)
3. Read `settings.json` → `safeJsonParse()` **(no validation)**
4. Read `pages/*.json` → `safeJsonParse()` (no validation)
5. Build new `JournalContent` with `schemaVersion: SCHEMA_VERSION`

## Target flow

1. Parse manifest via `parseManifest()`
2. Read `journal.json` → `safeJsonParse()` → `validateJournal()` (keep)
3. Read `settings.json` → `safeJsonParse()` → **`validateJournalSettings()`** (new)
4. Read `pages/*.json` → `safeJsonParse()` (no validation — pages are re-ID'd and rebuilt by construction)
5. Build new `JournalContent` with `schemaVersion: SCHEMA_VERSION`

## Changes

### Step 1: Update import.ts (native)

**File:** `src/lib/backup/import.ts`

Add `validateJournalSettings` to the existing canto-data import. After reading and parsing `settings.json`, call `validateJournalSettings(settings)` to validate at the boundary.

### Step 2: Update import.web.ts (web)

Same change as Step 1, applied to the web version.

### Step 3: Add tests

**File:** `src/lib/__tests__/backup.test.ts` (native)

1. **Current version passthrough**: Build a zip with current `schemaVersion` and valid settings. Import and verify settings are preserved unchanged.

2. **Invalid settings rejection**: Build a zip with malformed settings (e.g., `sort: "invalid"`). Import and verify it throws `ValidationError`.

**File:** `src/lib/__tests__/backupWeb.test.ts` (web)

Mirror the same test cases for the web import path.
