## Phase 3: Google Drive RemoteStore Implementation

### 3.1 Google Drive API helper (`src/lib/sync/gdrive/api.ts`)

- Thin wrapper around Google Drive REST API v3 using `fetch`
- Functions:
  - `listFiles(accessToken, query, spaces)` — list files with query filter
  - `getFile(accessToken, fileId)` — get file metadata
  - `getFileContent(accessToken, fileId)` — download file content
  - `createFile(accessToken, metadata, content, spaces)` — multipart upload
  - `updateFile(accessToken, fileId, metadata, content)` — update existing file
  - `deleteFile(accessToken, fileId)` — delete file
- All functions use `Authorization: Bearer ${accessToken}` header
- Use `spaces=appDataFolder` for the journal registry, regular Drive for journal data

### 3.2 Google Drive RemoteStore (`src/lib/sync/gdrive/store.ts`)

- Implements `RemoteStore` interface from `src/lib/sync/types.ts`
- **File structure on Drive:**
  - `appDataFolder/canto-journals.json` — registry of all synced journals (ID, title, encrypted flag)
  - `Canto/<journalId>/meta.json` — journal metadata (JournalContent minus pages array)
  - `Canto/<journalId>/pages/<pageId>.json` — individual page data
  - `Canto/<journalId>/attachments/<attachmentId>` — attachment binary data
- `connect(credentials)` — receives `{ accessToken: string }`, stores token
- `disconnect()` — clears token
- `isConnected()` — returns whether token is set
- `listRemoteJournals()` — reads `canto-journals.json` from appDataFolder
- `uploadJournalMeta()` — writes/updates meta.json and updates registry
- `downloadJournalMeta()` — reads meta.json, lists pages from folder to build page list
- `uploadPage()` / `downloadPage()` / `deletePage()` — CRUD on `pages/<pageId>.json`
- `uploadAttachment()` / `downloadAttachment()` / `deleteAttachment()` — CRUD on attachments folder
- Cache Drive file IDs in memory to avoid repeated lookups (file name → file ID map)

## Phase 5: Auto-Sync Trigger

### 5.1 Create sync manager (`src/lib/sync/manager.ts`)

- Singleton or context-based manager that:
  - On journal open (focus): if `autoSync && remoteSync && isSignedIn`, trigger sync
  - After page save: if `autoSync`, trigger sync for that journal (debounced, e.g. 5s)
  - Exposes `syncJournal(journalId)` for manual triggers
  - Manages sync state: `idle | syncing | error` per journal
  - Prevents concurrent syncs for the same journal (queue/lock)

### 5.2 Create `SyncManagerContext` (`src/contexts/SyncManagerContext.tsx`)

- Provides sync manager to the component tree
- Depends on `GoogleAuthContext` for access token
- Components can read sync state and trigger manual syncs

### 5.3 Integrate auto-sync into journal page (`app/journal/[id].tsx`)

- On focus: trigger sync if configured
- After page save (in page editor): notify sync manager
