## Implementation Plan

### Phase 1: Validation Polish (Issues #31, #32)

Both in `packages/canto-data/src/validation.ts`. Small, isolated changes.

#### Issue #31 — Add lat/lon range checks

`validateGeoLocation()` calls `checkNumber()` for latitude and longitude but doesn't validate ranges. Valid latitude is [-90, 90], longitude is [-180, 180].

**Fix:** Add range validation after the existing `checkNumber` calls:

```typescript
export function validateGeoLocation(v: unknown, path = 'location'): GeoLocation {
  checkObject(path, v);
  const o = v as Record<string, unknown>;
  checkNumber(`${path}.latitude`, o.latitude);
  checkNumber(`${path}.longitude`, o.longitude);
  if ((o.latitude as number) < -90 || (o.latitude as number) > 90) {
    throw new ValidationError(`${path}.latitude`, 'number in range [-90, 90]', String(o.latitude));
  }
  if ((o.longitude as number) < -180 || (o.longitude as number) > 180) {
    throw new ValidationError(
      `${path}.longitude`,
      'number in range [-180, 180]',
      String(o.longitude),
    );
  }
  checkOptionalType(`${path}.altitude`, o.altitude, 'number');
  checkOptionalType(`${path}.accuracy`, o.accuracy, 'number');
  return v as GeoLocation;
}
```

**Test:** `packages/canto-data/src/__tests__/validation.test.ts` — add cases for lat=91, lon=-181, lat=-90 (valid edge), lon=180 (valid edge).

#### Issue #32 — Reject empty/whitespace-only tags

Tags are validated only as strings via `checkString()`. Empty strings and whitespace-only strings pass.

**Fix:** Add a content check in the tags validation loop:

```typescript
checkArray(`${path}.tags`, o.tags);
for (let i = 0; i < (o.tags as unknown[]).length; i++) {
  checkString(`${path}.tags[${i}]`, (o.tags as unknown[])[i]);
  if (((o.tags as unknown[])[i] as string).trim() === '') {
    throw new ValidationError(`${path}.tags[${i}]`, 'non-empty string', '""');
  }
}
```

**Test:** `packages/canto-data/src/__tests__/validation.test.ts` — add cases for `""`, `"   "`, and `"\t"` tags.

### Phase 2: Minor Hardening (Issues #33, #34, #36, #39, #40)

Small fixes across multiple files. Independent of each other.

#### Issue #33 — Generate unique multipart boundary

**File:** `src/lib/sync/gdrive/api.ts` lines 91, 124

The hard-coded `'---canto-boundary---'` could collide with content.

**Fix:** Generate a random boundary per request:

```typescript
function generateBoundary(): string {
  const random = Array.from(crypto.getRandomValues(new Uint8Array(16)))
    .map((b) => b.toString(16).padStart(2, '0'))
    .join('');
  return `---canto-${random}---`;
}
```

Use `generateBoundary()` at the top of both `createFile()` and `updateFile()` instead of the hardcoded string.

**Test:** `src/lib/sync/gdrive/__tests__/api.test.ts` — verify the Content-Type header contains a unique boundary, and that a request with content containing the old boundary string doesn't corrupt.

#### Issue #36 — Verify tag normalization consistency

**File:** `src/components/page/TagEditor.tsx` lines 24-31

The `addTag` function already normalizes to lowercase via `tag.trim().toLowerCase()` at line 29. The comparison also uses `.toLowerCase()`. This means new tags are always stored lowercase.

**Potential issue:** Tags imported from backups or synced from other devices may retain original casing. The editor prevents adding duplicates within a session, but pre-existing mixed-case tags from external sources could coexist.

**Fix:** Add a normalization step when loading tags for display. In the `TagEditor`, normalize the incoming `tags` prop:

```typescript
const normalizedTags = useMemo(() => [...new Set(tags.map((t) => t.trim().toLowerCase()))], [tags]);
```

Use `normalizedTags` for display and comparison. This deduplicates on render without mutating the source data. Optionally, call `onChange(normalizedTags)` on mount if deduplication occurred to persist the cleanup.

**Test:** `src/components/page/__tests__/TagEditor.test.tsx` — pass `["Python", "python"]`, assert only one tag is rendered.

#### Issue #39 — Validate stored auth shape

**File:** `src/contexts/GoogleAuthContext.web.tsx` lines 62-80

`readStoredAuth()` does `JSON.parse(raw)` and trusts the shape matches `StoredAuth`.

**Fix:** Add a runtime shape check:

```typescript
function isValidStoredAuth(data: unknown): data is StoredAuth {
  if (!data || typeof data !== 'object') return false;
  const o = data as Record<string, unknown>;
  return (
    typeof o.accessToken === 'string' &&
    typeof o.storedAt === 'number' &&
    typeof o.retentionDays === 'number'
  );
}

function readStoredAuth(): StoredAuth | null {
  try {
    const raw = localStorage.getItem(STORAGE_KEY);
    if (!raw) return null;
    const data = JSON.parse(raw);
    if (!isValidStoredAuth(data)) {
      localStorage.removeItem(STORAGE_KEY);
      return null;
    }
    // retention check...
    return data;
  } catch {
    localStorage.removeItem(STORAGE_KEY);
    return null;
  }
}
```

**Test:** `src/contexts/__tests__/GoogleAuthContext.web.test.tsx` — set localStorage to `{"garbage": true}`, assert `readStoredAuth` returns null and removes the key.

#### Issue #40 — Add timeout to getAccessToken

**File:** `src/contexts/GoogleAuthContext.web.tsx` lines 187-214

`promptAsyncRef.current()` can hang indefinitely.

**Fix:** Wrap in a timeout:

```typescript
const AUTH_TIMEOUT_MS = 15_000;

function withTimeout<T>(promise: Promise<T>, ms: number, label: string): Promise<T> {
  return Promise.race([
    promise,
    new Promise<never>((_, reject) =>
      setTimeout(() => reject(new Error(`${label} timed out after ${ms}ms`)), ms),
    ),
  ]);
}

// In getAccessToken:
if (promptAsyncRef.current) {
  try {
    const result = await withTimeout(promptAsyncRef.current(), AUTH_TIMEOUT_MS, 'Silent re-auth');
    // ... handle result
  } catch {
    // Silent re-auth failed or timed out
  }
}
```

**Test:** `src/contexts/__tests__/GoogleAuthContext.web.test.tsx` — mock `promptAsync` to never resolve, assert `getAccessToken` returns null after timeout.

### Phase 3: Storage Cleanup (Issue #35)

#### Issue #35 — Clean up orphaned attachments on soft delete

**File:** `src/lib/storage/local.ts` lines 302-314 (and `local.web.ts`)

Soft-deleted pages keep their attachment files on disk. Over time this wastes storage.

**Fix:** After soft-deleting a page, schedule an attachment cleanup. Don't block the delete operation — run cleanup async:

```typescript
async deletePage(journalId: string, pageId: string, derivedKey?: Uint8Array): Promise<void> {
  const page = await this.getPage(journalId, pageId, derivedKey);
  if (!page) return;

  const deleted = { ...page, deleted: true, modified: Date.now() };
  await writeEncrypted(
    getPageFile(journalId, pageId),
    JSON.stringify(deleted),
    encryption,
    derivedKey,
  );

  // Clean up attachment files (non-blocking)
  this.cleanupPageAttachments(journalId, page).catch((err) => {
    console.warn(`[Canto] Failed to clean up attachments for page ${pageId}:`, err);
  });
},

async cleanupPageAttachments(journalId: string, page: Page): Promise<void> {
  const attachments = [...(page.images ?? []), ...(page.files ?? [])];
  for (const att of attachments) {
    if (att.path) {
      try {
        await this.deleteAttachmentFile(att.path);
      } catch {
        // Best-effort cleanup — file may already be gone
      }
    }
  }
}
```

Apply the same to `local.web.ts` (using IDB delete for attachment entries).

**Test:** `src/lib/storage/__tests__/local.test.ts` — soft-delete a page with attachments, assert attachment files are removed.

#### Issue #38 — Fix act() warnings in InfoBox test

**File:** `src/components/home/__tests__/InfoBox.test.tsx`

The async `loadChangelog` mock resolves after render, triggering state updates outside `act()`.

**Fix:** Wrap renders in `act()` and use `waitFor` for assertions that depend on async state:

```typescript
import { act, waitFor } from '@testing-library/react-native';

it('renders the help button', async () => {
  let result: ReturnType<typeof renderInfoBox>;
  await act(async () => {
    result = renderInfoBox();
  });
  expect(result!.getByText(tDict.help.title)).toBeTruthy();
});
```

Or simpler — use `waitFor` around the assertion:

```typescript
it('renders the help button', async () => {
  const { getByText } = renderInfoBox();

  });
});
```

**Test:** Run `npx jest InfoBox --verbose` and verify zero act() warnings in output.

## Risk Assessment

- **Phase 1 (validation):** Low risk — stricter validation. Existing data with out-of-range coordinates or empty tags will fail validation if re-validated. Only affects new writes and imports.
- **Phase 2 (hardening):** Negligible risk — additive checks, timeouts, and normalization
- **Phase 3 (cleanup):** Low risk — non-blocking cleanup after soft delete. If cleanup fails, behavior is same as current (files remain). No data loss path.
- **Phase 4 (tests):** Zero risk — only adds test coverage

## Dependencies

- Issue #36 (tag normalization) interacts with 17.3 Issue #32 (tag validation) — validation should land first
- Issue #35 (attachment cleanup) should land after 17.3 Issues #17-19 (storage deduplication) to avoid duplicating the cleanup logic in both platform files
- Issue #37b (FilterBar test) should include coverage for 17.3 Issue #25 (bidirectional sync fix)

## Execution Order

1. Phase 1 — validation changes in canto-data (independent package)
2. Phase 2 — independent hardening fixes, any order
3. Phase 3 — storage cleanup (ideally after 17.3 #17 dedup)
4. Phase 4 — tests last (they verify everything above)

## Questions for Review

1. **Issue #35 (orphaned attachments):** Should cleanup be immediate (blocking the delete) or async (fire-and-forget)? Async is faster but means storage isn't freed immediately. Also, should we add a periodic "garbage collection" sweep for attachments not referenced by any page?

2. **Issue #37 (test gaps):** The accessibility test (#37e) is broad. Should we limit it to a smoke test of the most critical components, or aim for comprehensive coverage of all interactive elements?

3. **Issue #36 (tag normalization):** Normalizing on render is safe, but should we also run a one-time migration to normalize existing tags in storage? This would prevent the dedup overhead on every render.
