# Plan: Repository Restructure (Requirement 1)

## Goal

Rebuild the Canto journaling app from scratch using a modern multi-platform framework with TypeScript, replacing the legacy React Native 0.66 + JS codebase.

## Framework Decision: Flutter vs React Native (Expo) vs Capacitor+SvelteKit

**Recommendation: Expo (React Native) with TypeScript**

Rationale:

- The original app is React Native — models, logic, and component structure can be ported incrementally
- Expo SDK 52+ provides managed workflow for Android, iOS, and web from a single codebase
- First-class TypeScript support out of the box
- EAS Build for reproducible builds without local Android Studio/Xcode setup
- Expo Router for file-based navigation (modern, well-supported)
- Large ecosystem for all needed features (encryption, file picking, GPS, markdown, Google Drive)
- Active community and strong documentation

Alternatives considered:

- **Flutter**: Great multi-platform but requires Dart rewrite of all logic; different ecosystem for encryption/GDrive libs
- **Capacitor+SvelteKit**: Good for web-first, weaker for native mobile features (camera, file system, encryption)

## Steps

### Step 1: Clean repo and initialize Expo project

- Remove all deleted legacy files from git tracking (they show as `D` in status)
- Initialize a new Expo project with TypeScript template (`npx create-expo-app`)
- Target: Android, iOS, Web

### Step 2: Project structure

```
canto/
├── app/                    # Expo Router screens (file-based routing)
│   ├── _layout.tsx         # Root layout with providers (theme, i18n)
│   ├── index.tsx           # Home screen (journal list)
│   ├── journal/
│   │   └── [id].tsx        # Journal screen (page list)
│   └── page/
│       └── [id].tsx        # Page screen (entry editor)
├── src/
│   ├── components/         # Reusable UI components
│   │   ├── common/         # Shared (Loader, Modal, Tag, etc.)
│   │   ├── home/           # Home-specific components
│   │   ├── journal/        # Journal-specific components
│   │   └── page/           # Page-specific components
│   ├── models/             # TypeScript interfaces & classes
│   ├── lib/                # Utility functions
│   ├── hooks/              # Custom React hooks
│   ├── i18n/               # Internationalization
│   ├── styles/             # Theme definitions
│   └── assets/             # Fonts, images
├── __tests__/              # Test files
├── .husky/                 # Git hooks
├── tsconfig.json
├── eslint.config.mjs       # ESLint flat config
├── prettier.config.mjs
├── app.json                # Expo config
├── package.json
└── README.md               # Build & run instructions
```

### Step 3: TypeScript configuration

- Strict mode enabled
- Path aliases (`@/components`, `@/lib`, etc.)
- Expo-compatible tsconfig base

### Step 4: Linting and formatting

- **ESLint** with flat config (eslint.config.mjs)
  - `@typescript-eslint` for TS rules
  - `eslint-plugin-react` and `eslint-plugin-react-hooks`
  - Prettier integration via `eslint-config-prettier`
- **Prettier** for code formatting
- Both as dev dependencies with npm scripts (`lint`, `lint:fix`, `format`)

### Step 5: Testing setup

- **Jest** with `jest-expo` preset (comes with Expo)
- **React Native Testing Library** for component tests
- npm scripts: `test`, `test:watch`, `test:coverage`
- One sample test for the hello world app to validate setup

### Step 6: Git hooks with Husky + lint-staged

- `pre-commit`: Run lint-staged (ESLint + Prettier on staged files)
- `pre-push`: Run type-check (`tsc --noEmit`)
- lint-staged config in package.json

### Step 7: Theme and i18n scaffolding

- Theme provider with light/dark mode support (React context)
- Theme type definitions matching original themes (colors, fonts)
- i18n scaffolding with language switching (en, pt)
- Store preferences with expo-secure-store or AsyncStorage

### Step 8: Hello World app

- Minimal app with:
  - Expo Router navigation working
  - Theme toggle (light/dark)
  - Language toggle (en/pt)
  - App name and logo displayed
- Verify it compiles and runs on:
  - Android emulator (`npx expo start --android`)
  - Physical Android device (Expo Go or dev build)
  - Web browser (`npx expo start --web`)

### Step 9: README with build instructions

Reproducible instructions covering:

- Prerequisites (Node.js, npm, Android Studio/emulator setup)
- `npm install`
- Running on Android emulator: `npx expo start --android`
- Running on physical device: `npx expo start` + scan QR with Expo Go
- Running on web: `npx expo start --web`
- Building APK: `npx expo run:android` or EAS Build
- Running tests: `npm test`
- Linting: `npm run lint`

### Step 10: Commit and tag

- Commit the complete scaffold
- Tag as `0.1.0` — fresh project foundation

## Risks & Mitigations

| Risk                                                                            | Mitigation                                                                                  |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Expo managed workflow may lack native modules needed later (e.g., MMKV, crypto) | Expo supports custom dev clients and config plugins; can eject to bare if absolutely needed |
| Expo Router is newer, may have quirks                                           | Well-documented, actively maintained, fallback to React Navigation directly                 |
| Android build on physical device requires USB debugging or Expo Go              | Document both paths in README                                                               |
