# Requirement 6: Cleanup 1

## Context

Canto has been built through requirements 1-5 (repo setup, styling, filesystem, journals, entries). The codebase is functional but has only 9.8% test coverage (4 test files, 33 tests), no CI/CD, no security tooling, no LICENSE file, and a minimal README. This cleanup round addresses test gaps, security hardening, tooling, structure, and presentation.

---

## Phase 1: Security Hardening

### 1.1 Add `clearKey()` to device encryption

**File:** `src/lib/encryption/device.ts`

- Add `clearKey()` method that zeros `cachedKey` with `.fill(0)` and sets to `null`
- Exposes ability to clear device key from memory on app background

**File:** `src/lib/encryption/types.ts`

- Add optional `clearKey?: () => void` to `EncryptionProvider`

### 1.2 Add `clearSession()` to encryption service

**File:** `src/lib/encryption/index.ts`

- Add `clearSession()` that calls device `clearKey()`

**File:** `src/lib/encryption/types.ts`

- Add `clearSession(): void` to `EncryptionService`

### 1.3 Add password strength validation

**File:** `src/lib/encryption/password.ts`

- Export `validatePasswordStrength(password: string): { valid: boolean; reason?: string }`
- Rule: minimum 8 characters (pragmatic, not over-engineered)

### 1.4 Add unlock rate limiting

**File:** `src/lib/encryption/ratelimit.ts` (new)

- Export `createUnlockRateLimiter()` returning `{ attempt(): boolean; reset(): void }`
- 5 attempts allowed, then locked for 30s. Pure logic, no deps.

### 1.5 Wire into UI

- `src/components/home/NewJournalModal.tsx` — use `validatePasswordStrength` to show error on weak passwords
- `src/components/home/JournalAccessModal.tsx` — use rate limiter on unlock attempts

### 1.6 Remove unused `expo-crypto`

**File:** `package.json` — remove from dependencies
