# Plan: Requirement 5 — Entries (Pages)

## Summary

Implement the full entry (page) system: creation, editing, preview with markdown rendering, encrypted/non-encrypted attachments (images, files), geo tags, tag management, comments, and save/delete operations. All entry data is always two-layer encrypted (device + password for secure journals). The disk format is designed for future export/import portability.

## Current State

- **Page model** exists in `src/models/types.ts` with `text`, `tags`, `images[]`, `files[]`, `comments[]`, `location`, `thumbnail`
- **Page screen** (`app/page/[id].tsx`) has basic view/edit toggle but no save, delete, attachment management, or markdown rendering
- **Journal screen** (`app/journal/[id].tsx`) has a FAB with `/* TODO: create page */`
- **Storage layer** has `savePage`, `getPage`, `deletePage`, `saveAttachment`, `getAttachment`, `deleteAttachment` all working with two-layer encryption
- **Hooks** have `usePage`, `useSavePage` — save hook exists but is never called
- **Attachment type** has `id`, `path`, `name`, `type: 'image' | 'file'`, `deleted` — no encrypted/non-encrypted distinction
- **Welcome page** auto-created in `useCreateJournal` — needs removal
- **No markdown renderer** installed

## Key Design Decisions

1. **Mixed encryption per attachment**: A single entry can have both encrypted and non-encrypted images/files. The `Attachment` type gets an `encrypted: boolean` field. Encrypted attachments get password-layer encryption on top of device encryption; non-encrypted attachments only get device encryption.
2. **Two separate carousels**: Unencrypted images in one carousel, encrypted images in another (with lock icon). Encrypted images decrypt asynchronously.
3. **Two add buttons** per attachment type: "Add Image" and "Add Encrypted Image" (same for files).
4. **Comments are encrypted**: Comments are part of the page JSON, which is always two-layer encrypted for secure journals.
5. **No welcome page**: Remove the auto-created welcome page from journal creation.
6. **Portability**: Each page is a self-contained JSON file. Attachments stored alongside with deterministic naming. This structure can be zipped as-is for export in a future requirement.

## Disk Format (unchanged, portability-ready)

```
DocumentDirectory/canto/
├── journals.json                              # device-encrypted index
├── {journalId}/
│   ├── metadata.json                         # device + password encrypted
│   ├── pages/
│   │   └── {pageId}.json                     # device + password encrypted
│   └── attachments/
│       ├── img-{pageId}-{hash}.{ext}         # device-only encrypted
│       ├── eimg-{pageId}-{hash}.{ext}        # device + password encrypted
│       ├── fl-{pageId}-{hash}.{ext}          # device-only encrypted
│       └── efl-{pageId}-{hash}.{ext}         # device + password encrypted
```

The `e` prefix distinguishes encrypted attachments on disk. Page JSON contains all metadata needed to reconstruct the entry, so exporting a journal = copying its directory.

## Resolved Decisions

1. **Image fullscreen viewer**: Use `react-native-image-viewing` library for fullscreen with pinch-zoom.
2. **Reordering images in carousel**: Use move-left/move-right arrow buttons in edit mode (no drag-to-reorder).
3. **Save behavior**: Manual save only (checkmark FAB). No auto-save. If user navigates away with unsaved changes, confirm discard.
4. **Attachment sizes**: No limits enforced.
