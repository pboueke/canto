# Plan 14.1: Address Unsupported Web Features

## Context

v0.14.0 added web platform support (IndexedDB storage, localStorage device keys, `.web.ts` overrides). However, several features still don't work or show broken UI on web. This plan addresses each one.

## Audit Results

### Working on Web (No Action Needed)

| Feature             | How                                                                    |
| ------------------- | ---------------------------------------------------------------------- |
| Storage (CRUD)      | IndexedDB via `local.web.ts`                                           |
| Device encryption   | localStorage via `device.web.ts`                                       |
| Password encryption | `@noble/hashes` (pure JS)                                              |
| AES-GCM encryption  | `expo-crypto` (has WebCrypto web impl)                                 |

## Steps

### Step 1: Hide Google Sign-In / Sync on Web

The `@react-native-google-signin/google-signin` web module throws "not implemented" (sponsors-only feature). All sync features must be hidden on web.

**Files to modify:**

- `src/components/home/AccountButton.tsx` — hide entirely on web (Google Sign-In button, account popover, manage journals)
- `src/components/journal/SyncModal.tsx` — hide sync button in journal header on web
- `src/components/journal/JournalSettings.tsx` — hide auto-sync toggle on web
- `src/contexts/GoogleAuthContext.tsx` — return null/no-op on web to prevent import of `@react-native-google-signin`

**Approach:** Add `Platform.OS === 'web'` checks at the component level to return null or hide sync-related UI. The GoogleAuthContext should use a `.web.ts` override that provides a no-op context (no Google Sign-In import).

**New files:**

- `src/contexts/GoogleAuthContext.web.tsx` — provides the same context shape but with no-op functions and `null` user. Never imports `@react-native-google-signin`.

### Step 2: Hide Export/Import UI on Web (or Implement)

**Option A (quick, recommended for now):** Hide export/import buttons on web.

- `src/components/journal/ExportMenu.tsx` — hide "Export" option on web
- `src/components/home/NewJournalModal.tsx` — hide "Import from Backup" option on web

**Option B (future):** Implement web export/import using:

- Export: `JSZip.generateAsync({ type: 'blob' })` → `URL.createObjectURL()` → anchor download
- Import: `<input type="file" accept=".zip">` → `FileReader` → `JSZip.loadAsync()`
- Both use the same backup format, just different I/O

Go with **Option A** for this plan. Option B can be a separate plan.

### Step 3: Fix `geo:` Links on Web

**File:** `src/components/page/LocationTag.tsx`

The `handlePress` function opens `geo:${lat},${lng}` which doesn't work in browsers.

**Fix:** On web, open `https://www.google.com/maps?q=${lat},${lng}` instead.

```typescript
const url =
  Platform.OS === 'web'
    ? `https://www.google.com/maps?q=${location.latitude},${location.longitude}`
    : `geo:${location.latitude},${location.longitude}`;
Linking.openURL(url);
```

### Step 4: Verify DateTimePicker on Web

**File:** `src/components/page/PageHeader.tsx`

Test `@react-native-community/datetimepicker` on web. If it renders a native browser `<input type="date">`, that's acceptable. If it crashes or shows nothing, add a Platform check.

This is a verification step — may not require code changes.

### Step 5: Update Web Compat Regression Test

Update `src/lib/__tests__/webCompat.test.ts` to also check for:

- `@react-native-google-signin/google-signin` imports (must have `.web.ts` counterpart or be behind Platform check)

Add `@react-native-google-signin/google-signin` to the `NATIVE_ONLY_MODULES` list.
