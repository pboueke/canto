## Reference App Differences

The original app used:

- **bcrypt** for password hashing (stored hash on JournalCover) — our new app uses **PBKDF2 + AES-256-GCM** (password derives encryption key, not a hash for comparison)
- **MMKV** for storage — we use **expo-file-system** with encrypted files
- **UUIDv5** for IDs — we can use `expo-crypto.randomUUID()` (simpler, no collision with deterministic IDs)
- **Feather icons** via react-native-vector-icons — we'll use **Feather icons** via `@expo/vector-icons` (bundled with Expo, no extra install)
- **Google Drive import** during creation — requirement says skip remote storage for now

Key insight: the reference app stores a bcrypt hash for password verification, then separately derives an encryption key with PBKDF2. Our architecture is simpler — the password IS the encryption key (via PBKDF2). We need to store the **salt** in journal metadata so it can be retrieved on other devices.

## Encryption Architecture — Key Caching

### Problem

The current `PasswordEncryptionProvider` calls `deriveKey()` (PBKDF2 with 600,000 iterations) on **every** encrypt/decrypt operation. This is intentionally slow (~200-500ms per call). Opening a journal with 50 pages would run PBKDF2 50 times — unacceptable.

### Solution: Derive once, cache in memory

Follow the same pattern `device.ts` already uses with its `cachedKey`:

1. **On journal unlock**: user provides password → PBKDF2(password, salt) → derived AES-256 key
2. **Cache the derived key** in a `Map<journalId, Uint8Array>` held in a React Context (`JournalKeyProvider`)
3. **All subsequent reads/writes** for that journal use the cached key directly with `aesGcmEncrypt`/`aesGcmDecrypt` — no PBKDF2
4. **On app close / journal lock**: zero and discard the cached key
5. **Salt stays in journal metadata** (base64-encoded) — portable across devices

### Storage layer changes

The `LocalStore` currently uses a single `EncryptionService` and always calls device-only `encrypt()`/`decrypt()`. For password-protected journals:

- Extend `LocalStore` (or create a wrapper) to accept an optional **pre-derived key** per journal
- When a key is present: `plaintext → AES-GCM(derived key) → AES-GCM(device key) → stored`
- When no key: `plaintext → AES-GCM(device key) → stored` (current behavior)

This avoids touching the `EncryptionService` interface — the derived key is used directly at the AES level, bypassing PBKDF2 entirely after the initial derivation.

### Flow diagram

```
Journal Creation (with password):
  password + generated salt → PBKDF2 (once) → derived key
  salt → stored in journal metadata (base64)
  derived key → cached in JournalKeyProvider
  welcome page → AES-GCM(derived key) → AES-GCM(device key) → filesystem

Journal Unlock:
  password + stored salt → PBKDF2 (once) → derived key → cached
  all pages → decrypt with cached key (fast, no PBKDF2)

Journal Lock / App Close:
  cached key → zeroed and removed from map
```

### Step 2: Create `JournalKeyProvider` context

**File:** `src/contexts/JournalKeyContext.tsx` (**New**)

React Context that holds a `Map<journalId, Uint8Array>` of derived encryption keys:

- `deriveAndCache(journalId, password, saltBase64)` — runs PBKDF2 once, stores result

### Step 3: Extend `LocalStore` for per-journal password encryption

**File:** `src/lib/storage/local.ts` + `src/lib/storage/types.ts`

Add optional `derivedKey` parameter to operations that need it:

- `saveJournal(journal, derivedKey?)`
- `getJournal(id, derivedKey?)`
- `savePage(journalId, page, derivedKey?)`
- `getPage(journalId, pageId, derivedKey?)`

When `derivedKey` is present, use two-layer encryption:

- Encrypt: `aesGcmEncrypt(data, derivedKey)` → `aesGcmEncrypt(result, deviceKey)`
- Decrypt: `aesGcmDecrypt(data, deviceKey)` → `aesGcmDecrypt(result, derivedKey)`

Export `aesGcmEncrypt`/`aesGcmDecrypt` from encryption utils (already exported internally).

## Open Questions / Decisions

1. **Entry count on JournalCard**: The `Journal` type doesn't store page count. **Recommendation: skip for now, can add later.**

2. **Page route restructuring**: Currently `/page/[id]` with no journal context. Need `journalId` for storage calls. **Recommendation: pass journalId as a query parameter** (`/page/[id]?journalId=xxx`) to avoid breaking the route structure.

3. **Password verification**: Since we don't store a hash (unlike the reference app's bcrypt), how do we know if the password is wrong? **Answer: AES-GCM authentication will fail** — `gcm.decrypt()` throws if the key is wrong (GCM tag won't match). We catch this and show "wrong password."
