## 3. Password Validation Bug Fix

### Problem

When a user enters a wrong password in `JournalAccessModal`:

1. `deriveAndCache()` runs PBKDF2 — always succeeds (produces a wrong key)
2. Navigation to `/journal/{id}` happens with the wrong key cached
3. Journal screen tries to decrypt with wrong key → AES-GCM fails → `journal = null`
4. User sees "Journal not found" instead of "Wrong password"

### Fix

In `app/index.tsx` `handleUnlock()`, after `deriveAndCache()`, attempt a **trial decryption** before navigating:

- Call `store.getJournal(journalId, derivedKey)` immediately after deriving the key
- If it returns `null` or throws (AES-GCM auth failure), the password is wrong:
  - Clear the bad key with `clearKey(journalId)`
  - Set `accessError(t.home.wrongPassword)`
  - Do NOT navigate
- If it succeeds, proceed with navigation

This keeps the fix localized to the home screen unlock flow. The journal data loaded during validation can be discarded (it will be re-loaded by the journal screen).

## 5. Per-Journal Theme Override

### Concept

Each journal can optionally override the global theme. When a user opens a journal, the journal's theme takes effect for all screens within that journal (journal page list, entry editor, settings). When the user returns to the home screen, the global theme resumes.

### 5a. Data model changes

Update `JournalSettings` in `src/models/types.ts`:

- Add `themeOverride?: string` — stores the theme name, or `undefined`/absent to use global theme
- Update `DEFAULT_JOURNAL_SETTINGS` to include `themeOverride: undefined`

### 5b. Theme override in journal creation

When a journal is created (`NewJournalModal` / `useCreateJournal`), the `themeOverride` defaults to `undefined` (use global theme). No UI change needed at creation time — the requirement says "when created, use the currently global theme" which means no override is stored, the journal just inherits the global theme.

### 5c. Add theme selector to JournalSettings

In `src/components/journal/JournalSettings.tsx`:

- Add a "Theme" section under Display Settings
- Show the current effective theme name (override or "Global: {name}")
- Tapping opens a theme picker (reuse `ThemePickerModal` from step 1b) with an additional "Use global theme" option at the top
- When a theme is selected, update `journal.settings.themeOverride` and persist

### 5d. Apply theme override when entering a journal

The theme override needs to take effect when navigating into a journal and revert when leaving.

Approach — **theme override context layer**:

In `app/journal/[id].tsx` and `app/page/[id].tsx`:

- After loading the journal, check `journal.settings.themeOverride`
- If set, wrap the screen content in a `ThemeContext.Provider` with the override theme, effectively shadowing the global theme for all children
- This is clean because `useTheme()` will naturally pick up the nearest provider
- The home screen and root layout keep the global theme unaffected

For the page screen (`app/page/[id].tsx`), the journal's theme override needs to be passed down. Options:

- Read the journal metadata in the page screen to get the override (the page screen already has `journalId` from params)
- Or store the active override in a lightweight context/ref that gets set when entering a journal

Simpler approach: add a `useJournalThemeOverride(journalId)` hook that reads just the journal settings to extract `themeOverride`. Use this in both `journal/[id].tsx` and `page/[id].tsx` to wrap content in an overriding `ThemeContext.Provider` when applicable.

### 5e. Dictionary additions

Add to all dictionaries:

- `journalSettings.themeOverride` — "Theme" / "Tema" / etc.
- `journalSettings.useGlobalTheme` — "Use global theme" / "Usar tema global" / etc.
