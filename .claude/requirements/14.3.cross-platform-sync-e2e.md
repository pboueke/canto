- The existing gdrive-sync-e2e.test.ts only tests native-like sync (single LocalStore mock, no platform-specific behavior)
- There is no test coverage for cross-platform sync scenarios (web ↔ native)
- Web and native use different LocalStore implementations (IndexedDB vs expo-file-system) with subtle differences:
  - Different attachment path formats (virtual IDB paths vs native file URIs)
  - Different encryption backends (localStorage device key vs expo-secure-store)
  - savePage() overwrites `modified` with Date.now() on both platforms — this silently destroys the remote timestamp during download, breaking conflict resolution on subsequent syncs
- Cross-platform sync is the primary real-world use case (user edits on phone, syncs, then opens on web or vice versa)
- Need three e2e test suites:
  1. Web-equivalent of the existing native e2e flow (web LocalStore mock through full sync lifecycle)
  2. Web → native sync flow (journal created/edited on web, synced to GDrive, then pulled down on native)
  3. Native → web sync flow (journal created/edited on native, synced to GDrive, then pulled down on web)
- Tests must cover: page CRUD, conflict resolution, deletion propagation, attachment round-trips, encrypted journals, and journal settings/metadata preservation across platforms
- Tests must verify data integrity: content written on one platform must be readable on the other after sync
- Tests must catch platform-specific inconsistencies (e.g. path format mismatches, timestamp mutation, encryption layer differences)
