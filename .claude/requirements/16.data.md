- journal data must not only be store from intruders, but also from corruption. As canto progresses, journal schema may change. Canto journals need to be very well documented, both in terms of object schemas and filesystem structure so data portability goals can be achieved
- a canto user should be able to create a ts application to directly manipulate canto journals. An open library for canto journal data model handling needs to exist, and be the one used by the canto app itself
- A DATA.md file needs to be added explaining exactly how one can use the canto TS models to interact with their exported data
- as a future proofing measure, canto journal models need to be versioned along side the canto app repositry. Breaking changes in this context (MAJOR bump) mean that a migration is needed. Minor and Patch versions mean no migration is needed. The Canto model library needs to be the one responsible for journal version migrations
